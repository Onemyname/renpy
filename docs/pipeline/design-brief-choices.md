# Бриф для дизайн-итерации: экран выбора ответов

Скопируйте этот файл целиком в новую сессию Claude как задачу. Он самодостаточен:
описывает контракты, которые нельзя нарушать, и ровно те механизмы, которые уже
доступны — чтобы дизайн не упёрся в движок и не потребовал переделки конвейера.

---

## Задача

Спроектировать и реализовать **визуальный дизайн экрана выбора ответов** (`screen
choice`) для коммерческой визуальной новеллы на Ren'Py 8.5.3. Это самое
уязвимое место интерфейса: выбор — единственный момент, когда игрок
взаимодействует с игрой, и сейчас он выглядит как набор плоских серых полос.

Файлы, которые предстоит менять:

- `game/framework/20_ui/screens/choice.rpy` — сам экран и его стили
- `content/ui/panels.yaml` — параметры генерируемых фонов (радиусы, тени, градиенты)
- `game/framework/20_ui/components.rpy` — если понадобятся переиспользуемые части
- `game/gui.rpy` — токены (палитра, размеры, шкала отступов), если чего-то не хватает
- `content/ui/strings.yaml` — если появятся новые подписи (только через ключи!)

## Что уже сделано и чем можно пользоваться

**Скругления, мягкие тени, градиенты и обводки — доступны.** Ren'Py не рисует их
на `Solid`, поэтому в проекте есть генератор: панели объявляются в
`content/ui/panels.yaml`, конвейер рисует 9-patch и эмитит `Frame`-образы
`vn_frame_<id>`. В стилях пишете `background vn_frame_choice_hover` — ни путей,
ни пикселей в вёрстке. Правка радиуса = правка YAML + `vn build`. Подробности —
`docs/adr/0009-generated-ui-panels.md`.

Уже объявлены: `choice`, `choice_hover`, `choice_chosen`, `panel`, `slot`, `toast`.
Добавлять новые — свободно.

**Ловушка геометрии, которую нельзя нарушить:** `Borders = radius + (blur + |dy|)`,
и элемент **не может быть меньше `2*Borders`** — иначе движок сожмёт фон и кнопка
превратится в тонкую пилюлю (уже случалось). Минимальный размер каждой панели
печатается в `game/generated/registry/ui_frames.gen.rpy` — сверяйтесь с ним.

**Шрифты:** Literata (диалоги), Inter Regular/SemiBold (интерфейс) — через токены
`gui.text_font` / `gui.interface_text_font` / `gui.interface_semibold_font`.
Кириллица и латиница с умляутами покрыты. Хардкодить `font "..."` в стилях
нельзя — языковые пакеты переопределяют шрифты через `gui.*`.

**Данные, доступные для каждого пункта** в `screen choice(items)`:

- `i.caption` — текст (но выводить надо через `vn_loc.choice_text`, см. ниже)
- `i.action` — действие
- `i.chosen` — **этот вариант уже выбирали в предыдущем прохождении**; отличный
  повод визуально отличать «новое» от «пройденного» (сейчас не используется)
- `enumerate(items)` — индекс для нумерации/горячих клавиш

## Жёсткие контракты — нарушать нельзя

1. **Текст пункта — только через `vn_loc.choice_text(vn_menu, idx, i.caption)`.**
   Это механизм локализации (норма G8/C1): перевод ищется по паре
   «id меню + индекс». Подставите `i.caption` напрямую — переводы перестанут
   работать, и никто не заметит до релиза на другом языке.

2. **Никаких строковых литералов в экранах.** Любая подпись — ключ в
   `content/ui/strings.yaml` + `vn_loc.t("ui.…")`. Литерал не попадёт в
   PO-экстракцию и останется непереведённым. Если добавляете ключи — переводы на
   `en`/`de` обязательны, иначе релизный гейт покрытия (98%) покраснеет.

3. **Блок QA-автопилота сохранить дословно:**
   ```renpy
   if vn_qa.autopilot_active():
       timer 1.0 action Function(vn_qa.autopilot_choose, items) repeat True
   ```
   Без него ломается `vn test smoke` — автопрохождение в CI.

4. **Сигнатура `screen choice(items)`** — фиксирована движком, не менять.

5. **Никаких бинарных ассетов вручную.** Всё оформление — через
   `content/ui/panels.yaml` (генерируется) либо чистый Ren'Py. Картинки в git не
   коммитим.

## Известные проблемы текущего вида

1. Фиксированная ширина `xsize 820` независимо от длины текста — короткий вариант
   («Промолчать») выглядит пустым, длинный может не помещаться.
2. Нет отклика на наведение/фокус, кроме смены фона — ни движения, ни акцента.
3. Нет клавиатурных и геймпадных аффордансов: непонятно, какой пункт в фокусе и
   можно ли выбирать цифрами.
4. Нет визуальной иерархии: все варианты равнозначны, хотя бывают «обычный ответ»
   и «ключевое решение».
5. `i.chosen` не используется — при повторном прохождении не видно, что уже пробовал.
6. Позиция `ypos 296` жёсткая: при трёх-четырёх вариантах композиция поедет.
7. Затемнение сцены — плоский `Solid("#00000061")` на весь экран.

## Что хочется получить

Выбор должен читаться как **осознанный момент решения**, а не как список кнопок:

- современный вид (скругления, глубина, аккуратная типографика);
- явный фокус — понятно, что выбрано сейчас, работает мышью и клавиатурой;
- живость без суеты: микро-анимации на наведении/появлении, ATL-переходы;
- масштабируемость: 2 варианта и 5 вариантов выглядят одинаково хорошо;
- различимость состояний: обычный / под курсором / уже выбранный ранее / недоступный;
- уместность для эротической визуальной новеллы: тёмная тема, тёплый акцент,
  без «корпоративного» вида и без вульгарности.

Свобода в композиции полная: варианты могут быть карточками, строками с
акцентной полосой, с номерами, с иконками-глифами из шрифта — что угодно, что
достижимо перечисленными средствами.

## Приёмка (обязательно прогнать)

```bash
vn build                       # схемы, панели, генерат
"$RENPY_SDK/renpy.exe" . lint  # движковый lint — должен быть чист
vn loc report                  # покрытие переводов: все языки 100%
vn test smoke --picks 0,0      # автопрохождение; скриншоты в .vncache/smoke/
python -m pytest tools/vn/tests -q
```

Обязательно **посмотреть скриншоты** `.vncache/smoke/shot*.png` — движковый lint
не ловит визуальные поломки (сплющенные фоны, обрезанный текст, тофу вместо
глифов). Проверить оба состояния: 2 варианта (`ch01_s010`) и вид при наведении.

Хорошая практика: прогнать `vn test smoke --lang de` и `--lang pseudo` —
псевдолокализация удлиняет строки на 40% и показывает, переживёт ли вёрстка
длинные переводы.

## Чего делать НЕ надо

- не трогать логику ветвления, `exits`, компилятор и тулинг — это не дизайнерская зона;
- не вводить условные пункты меню (`"текст" if условие:`) — компилятор их
  запрещает, причина в переводе по индексу; условные ответы делаются ветвлением сцены;
- не добавлять зависимости и внешние библиотеки;
- не делать «тему» с десятком вариантов — нужен один хороший вид.
