# ADR-0005: Языковые пакеты с автодискавери и рантайм-реестр языков

- **Статус:** принято
- **Дата:** 2026-08-07
- **Затрагивает нормы:** G8, C1, раздел 5 (5.4/5.5/5.11), раздел 7 (экран настроек)

## Контекст

Фаза 2 локализации оставила три проблемы:

1. **«Смена языка не работает».** UI-строки экранов (`_("Настройки")` и т.д.)
   не проходили через PO-экстракцию: конвейер собирал только диалоги (ledger),
   `content/ui/strings.yaml` и имена персонажей. Переключение языка меняло
   диалоги, но весь интерфейс — то, на что смотрит игрок в момент переключения, —
   оставался на исходном языке.
2. **Ручная регистрация языков.** Список языков жил в `loc/loc.yaml languages:`
   и эмитился в `define VN_LANGUAGES`; `pseudo` приписывался отдельной веткой
   в двух местах (`compile.py`, `po.py`). Добавление языка = правка конфига +
   пересборка; DLC/моды не могут привезти язык вообще.
3. **UI выбора языка** — горизонтальная строка сырых кодов `ru en pseudo`,
   не масштабируется и не показывает native-названия.

## Решение

**Язык = самоописывающийся пакет `loc/po/<code>/` с манифестом `language.yaml`
(schema `language@1`: `code`, `name` — native-название, опц. `font`, `synthetic`).
Списка языков нет нигде: тулинг и рантайм сканируют пакеты.**

1. **Автодискавери в тулинге.** `extract`/`import`/`report` обходят
   `loc/po/*/language.yaml`. `loc/loc.yaml` мигрирован на `loc@2`: описывает
   только исходный язык (`source: {code, name}`) и релизные пороги; поля
   `languages:` больше нет. `pseudo` — обычный пакет с `synthetic: true`,
   который создаёт `vn loc pseudo` и регенерирует каждый `vn loc extract`
   (псевдолокализация не отстаёт от исходников; генератор существует только
   для кода `pseudo` — другой synthetic-пакет получает warning «без
   генератора»). Новый язык скаффолдит `vn loc add <code> [--name]`.
2. **Рантайм-манифесты.** `vn loc import` кладёт в `game/tl/<code>/`
   `language.json` (код, native-название, шрифт) и гарантирует каждому языку
   хотя бы один translate-стейтмент (`translate <code> python`, там же —
   языкозависимый шрифт из манифеста): `renpy.known_languages()` видит только
   языки с translate-блоками.
3. **Language Registry.** `game/framework/00_core/040_localization.rpy`
   (слой ядра: реестр не знает глав/персонажей — правило 1.8; `10_systems`
   оставлен удаляемым геймплей-плагинам), named store `vn_lang` —
   единственный источник знания о языках в рантайме: `available()`
   (сканирует `renpy.known_languages()` + `tl/*/language.json`; исходный
   язык из `define VN_SOURCE_LANG` — эмитится компилятором из `loc.yaml`),
   `current()`, `set(code)`, `action(code)` (для экранов), `subscribe(fn)`.
   Уведомления — через движковый `config.language_callbacks[lang]`
   (per-language; `refresh()` регистрирует хук на каждый обнаруженный язык
   и на `None`): срабатывает при любом пути смены языка. ВАЖНО:
   `config.change_language_callbacks` в Ren'Py 8.5 — мёртвый список
   («Removed.» в config.py), движок его не вызывает — не «упрощать» на него.
   `define VN_LANGUAGES` удалён. Мод/DLC, привёзший `tl/<code>/`,
   появляется в настройках без кода.
4. **UI-строки — через ключи.** Все литералы экранов перенесены в
   `content/ui/strings.yaml` (`ui.*`) и читаются `vn_loc.t(key)` —
   id-based lookup из 5.3/5.4 без коллизий `translate strings`;
   ретрансляция горячая: `renpy.change_language` перезапускает интеракцию,
   экраны переоцениваются. Движковые confirm-подсказки (Quit/MainMenu/FileLoad)
   заменены обёрткой `Confirm(vn_loc.t(...), Action(confirm=False))` — иначе
   игрок видит английские строки движка.
5. **Экран выбора языка** — вертикальный список native-названий в viewport
   (скроллбар, мышь/колесо/драг, клавиатура/геймпад через focus, автопрокрутка
   к выбранному через `yinitial`), стили — отдельные `pref_lang_*`.
   `synthetic`-языки видны только при `config.developer`.

Уточнение 5.4: канонический механизм UI-строк — id-lookup `vn_loc.t()`
(как для меню в 5.3), а не `translate strings`; `translate strings` остаётся
для имён персонажей и движковых строк. Коллизионный CI-гейт из 5.4 не нужен:
идентичность ключевая, а не текстовая.

## Последствия

- Добавление языка: `vn loc add de --name Deutsch` → перевод PO → `vn loc
  import`. Ни одной правки кода/конфига; язык сам появляется в настройках.
- `loc@1` остаётся в реестре схем (история); `loc.yaml` мигрирован на `loc@2`.
- Каталог `loc/po/<code>/` без `language.yaml` — ошибка дискавери с подсказкой
  (`vn loc add`), лint валидирует манифесты по `language@1` и сверяет
  `code` с именем каталога.
- Шрифты: пакет языка может объявить `font:` (например, CJK) — он применяется
  `translate <code> python` и используется для native-названия в списке языков.
  Пока ни один язык шрифт не объявляет; поставка шрифта — на пакете языка.
- Откат: механизм PO/tl не менялся — вернуть `languages:` в конфиг можно
  одним коммитом, пакеты обратно-совместимы (PO-файлы не переехали).
