# ADR-0013: Послойные полнокадровые шоты (shots@1)

- **Статус**: принято
- **Дата**: 2026-08-17
- **Затрагивает нормы**: G11 (канон layeredimage-эмиттера — переиспользуется), G5
  (гардероб — переменная Variable Registry), дополняет раздел 4 ARCHITECTURE.md
  новым классом ассетов `shot`

## Контекст

Конкурентный аудит (docs/competitive-audit-freshwomen.md, §2.4/§17) показал
единственное архитектурное решение референса, которого у нас не было: кадр
кинематографического шота там — не одна картинка, а до шести слоёв, собираемых
в рантайме, с подменой наряда персонажа без перерендера кадра.

Наша модель до этого ADR выражала два вида кадра: `spr` (переиспользуемый
спрайт поверх `bg`) и `cg` (плоский полнокадровый стилл). Для
DAZ-фотореалистичной новеллы плоский `cg` — комбинаторный взрыв: «героиня в
трёх нарядах × 70 шотов сцены» = 210 полных 4K-рендеров вместо 70 подложек +
3 слоёв. Это упирается и в бюджет рендер-фермы, и в 20 ГБ бюджета дистрибутива
уже на второй главе. Решение требовалось принять ДО старта массового
производства контента: пост-фактум это перерендер всего.

Референс при этом скопирован быть не может: там композиция держится на
перехвате стейтмента `show`, шести служебных слоях Ren'Py, ручном словаре
z-порядков без валидации, проверке существования слоёв в рантайме
(`renpy.has_image` — опечатка молча даёт кадр без персонажа) и переборе скинов
callback'ом 20 раз в секунду. Каждый из этих приёмов ломает то, на чём стоит
наша архитектура: статическую валидацию, prediction, rollback и генерат как
единственный источник кода.

## Решение

Шот — это данные, композиция — нативный `layeredimage`, один на сцену.

1. **Декларация** — `content/chapters/chNN_slug/shots/sNNN.shots.yaml`
   (`schema: shots@1`): шоты сцены, слои каждого шота, ЯВНЫЙ z-порядок
   (`order`, обязан перечислить каждый слой ровно один раз), варианты слоя и
   опционально переменная гардероба (`var`).
2. **Мастера** — `assets_src/art/shots/<chNN>/<sNNN>/<shot>/<layer>[__<variant>].<ext>`,
   класс `shot` render-профиля (project.yaml). `env` — обязательная
   непрозрачная подложка, задаёт холст; остальные слои обязаны нести альфу и
   лежать на том же холсте (layeredimage кладёт слои в (0,0)). Оверсэмпл
   `@N` — как у всех растровых классов. Источник слоёв в производстве — DAZ
   Canvases: один проход рендера даёт слои без удорожания рендера.
3. **Эмиссия** (канон G11) — один `layeredimage shot_<chNN>_<sNNN>` на сцену:
   селекторная группа `shot` (`attribute <id> default Null()`), слои шота в
   порядке `order`, гейт `if_any ["<shot>"]`. Смена шота = смена атрибута:
   групповая эксклюзивность сама снимает предыдущий, а липкость атрибутов тега
   сохраняет выбранный наряд между шотами сцены — то, что референс делает
   монкипатчем, здесь даёт движок штатно.
4. **Гардероб** — слой с `var:` получает дефолтный атрибут `<layer>_auto`:
   `ConditionSwitch` по переменной Variable Registry (значение = имя варианта,
   ветка по умолчанию — первый вариант). Rollback, save/load и смена наряда
   посреди сцены работают штатно; `predict_all=True` прогревает все ветки.
   Явные атрибуты `<layer>_<variant>` позволяют сценаристу переопределить
   выбор на конкретном шоте.
5. **Валидация — на сборке, не в рантайме**: схема; сцена-владелец существует;
   `order` ↔ `layers`; `var` объявлена в реестре (иначе гардероб не попал бы в
   сейв, G5); каждый объявленный слой/вариант собран (иначе ошибка сборки,
   битый layeredimage не эмитится); собранный, но не объявленный слой —
   предупреждение. Ссылки `show shot_… <шот> <вариант>` в сценах сверяются
   индексом образов как у персонажей.
6. **Модель памяти** учитывает худший шот сцены (env + самый тяжёлый вариант
   каждого слоя) — полнокадровые композиции не проходят мимо бюджета кэша.
7. **Реестры**: id слоёв (`shots/...`) — выпущенные id ассетов наравне с
   `bg|cg|spr|mov` (id_registry@1, renames@1, `built_asset_ids`).

## Последствия

- Наряд на полнокадровом шоте перестаёт умножать рендеры: N подложек + M слоёв
  вместо N×M полных кадров — и в производстве, и в дистрибутиве, и в кэше.
- Ошибки композиции (нет слоя, опечатка в варианте, кривой z-порядок,
  недекларированная переменная) — красная сборка, а не молчаливо пустой кадр
  у игрока.
- Ограничение: у `env` вариантов не бывает — вариативная среда объявляется
  отдельным шотом. Это осознанно: env задаёт холст и валидационный якорь.
- Галерея пока адресует только плоские ассеты (`cg|bg|mov`): элемент галереи
  для послойного шота потребует либо экспорта плоского кадра, либо расширения
  gallery@1 — отдельным решением, когда появится реальный контент.
- План отступления: shots@1 — чистая надстройка (схема + ветка конвейера +
  эмиттер); откат = удаление деклараций и зоны мастеров, сцены на `cg` не
  затрагиваются. Выпущенные id слоёв защищены реестром как обычно.
