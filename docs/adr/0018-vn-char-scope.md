# ADR-0018: `vn char` реализуется в урезанном объёме; четыре обещания нормы снимаются

- **Статус**: принято. `vn char new`, `vn char validate` и `vn char sheet` реализованы (перестали
  быть заглушками фазы). Четыре подробности, которые норма обещала у этих команд, **из нормы
  убраны** — под них нет ни данных, ни потребителя.
- **Дата**: 2026-08-18
- **Затрагивает нормы**: раздел 4 `ARCHITECTURE.md` (персонажи: §4.5 «полнота матрицы»,
  формулировка «обязательный шаг CI» у `vn char validate`); G1 (единый CLI, команда либо делает
  работу, либо её нет); ADR-0012 (холст мастеров: `validate` теперь называет фактический размер);
  ADR-0009 (лист ревью — производный артефакт, в git не едет).

## Контекст

Персонаж — вторая по частоте единица работы после сцены, и цель проекта — 150+ персонажей. При
этом заводился он руками по схеме, а ошибки матрицы (нет `base` у позы, наряд вне `matrix`,
запрещённая комбинация всё-таки собрана) всплывали на середине `vn build`: цикл «поправил слой →
30-секундная сборка → сообщение» вместо мгновенной проверки.

Важная деталь, которая определила решение: **проверки уже существовали** — целиком, внутри
`emit_images` (`content/images.py`), то есть внутри генерации кода. Написать для команды «свои»
проверки означало бы завести вторую реализацию контракта полноты, которая разойдётся с первой на
первой же правке. Расхождение здесь — это «зелёный `char validate` при красном `vn build`», что
хуже отсутствия команды.

## Решение

1. **Контракт полноты матрицы вынесен в одну функцию** — `images.check_matrix(rel, doc,
   poses_files, rep) -> список эмитируемых поз`. Её зовут ровно два потребителя: эмиттер
   layeredimage (как раньше) и `vn char validate`. Формулировки ошибок не менялись; тесты сборки
   остались зелёными без правок, и это главное доказательство, что вынос — рефакторинг, а не
   переписывание.
2. **Геометрия мастеров вынесена так же** — `assets.pipeline.character_jobs(..., only=<id>)` —
   ветка `_discover`, отвечающая за формат, альфу, `source_min` и **единство холста**. `validate`
   зовёт её с фильтром по персонажу и выбрасывает задания: нужен только отчёт, ни один байт не
   пишется (проверяется тестом по mtime всего дерева).
   Почему не `build_assets(check=True)`: полный проход тянет видео-ветку, и без ffmpeg проверка
   персонажа краснела бы из-за тракта, к персонажу не относящегося.
3. **`vn char new` — скаффолдер, а не шаблон «на будущее»**: декларация, валидная по `character@1`
   с первой секунды, плюс каталог мастеров. Каталог **позы** не создаётся: папка позы без `base.*`
   мгновенно валит `vn assets build`, то есть скаффолд оставлял бы дерево красным. Цвет реплик
   выводится из хеша id (обязательное поле схемы; «выберите сами» на скаффолде означало бы, что
   первые пять персонажей получат один и тот же цвет из примера).
4. **`vn char sheet` — лист арт-ревью** `build/review/<id>/index.html`: ячейки-композиции всех
   допустимых комбинаций поза+наряд+эмоция, склеенные `imaging.composite` в том же z-порядке, что
   эмитирует layeredimage (`images.LAYER_ORDER`). Подложка ячейки — средне-серая: слои спрайта это
   вырезы с альфой, на белом теряются светлые контуры, на чёрном — тёмные. Запрещённые
   декларацией комбинации в лист не попадают: ревью того, чего в игре не будет, вводит в
   заблуждение. Замечания валидатора печатаются на той же странице — ревьюер видит и картинку, и
   причину, по которой сборка красная.

## Что из нормы снято (и почему)

| Обещание нормы | Почему снято |
|---|---|
| `vn char new --template <id>` | Поля «шаблон» в `character@1` нет вовсе; копирование чужой декларации даёт матрицу, которой у нового персонажа нет ассетов. Появится вместе с `character@2`, если понадобится |
| `vn char sheet --light warm_sunset` | Световых профилей в тулинге не существует: `location@1.lighting` не читает ни одна строка кода. Команда рисовала бы освещение, которого в игре нет |
| `vn char validate --report build/matrix_report.html` | HTML-артефакт у персонажа один — лист ревью, и он уже содержит блок замечаний. Второй отчёт про то же — второе место, которое разойдётся |
| Offset-рамки, автор и дата сырца в ячейках листа | Trim-офсеты конвейер не считает (обрезка идёт по bbox при сборке), а у зоны `art/` нет манифестов `asset_src@1` — автора и дату брать физически негде |

Отдельно исправлена формулировка §4.5: `vn char validate` **не** «обязательный шаг CI». Гейт
полноты матрицы исполняет `vn build`, который CI и так гоняет, причём тем же кодом. Второй прогон
того же в MR-пайплайне противоречил бы G15 (бюджет пайплайна < 10 минут) и не добавлял бы ни одной
новой проверки.

## Последствия

- Заглушек в дереве команд осталось три (`test replay|screens|paths`) плюс `save migrate`.
- Художник получает цикл в секунды: `vn char validate <id>` не требует ни SDK, ни ffmpeg, ни
  сборки ассетов — при этом отвечает теми же словами, что потом скажет `vn build`.
- `build/review/` — производный артефакт: в git не едет (`.gitignore: build/`), в дистрибутив не
  попадает (`options.rpy: build.classify("build/**", None)`), перезаписывается целиком при каждом
  прогоне.
- Риск: `char validate` видит только то, что уже СОБРАНО в `game/assets`. Мастер, положенный
  минуту назад, в отчёт не попадёт, пока не пройдёт `vn assets build`; команда об этом говорит
  прямым текстом («статика появится после vn assets build»), но перепутать состояния всё ещё
  возможно.
