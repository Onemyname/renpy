# ADR-0021: Флоучарт, walkthrough и реплей сцен — три проекции одного скомпилированного графа

- **Статус**: принято
- **Дата**: 2026-08-22
- **Затрагивает нормы**: дополняет G5 (граф истории как build-time артефакт),
  G24 (разбор `.rpy` только парсером Ren'Py — расширяется мост, не появляется
  второй разборщик), C1 (адресация выбора парой `(vn_menu, idx)` становится
  несущей для подсказок), C9 (состояние плана — плоский `persistent.vn_*`),
  C10 (тестовый контент живёт паком), ADR-0010 (закрывает открытый пункт про
  реплей сцен из галереи)

## Контекст

Конкурентный аудит (`docs/competitive-audit-reclaiming.md` §4.2–4.3) показал две
продуктовые фичи жанра, которых у нас нет: встроенный walkthrough (игрок
отмечает целевые сцены, игра подсвечивает нужные выборы) и реплей сцен из
галереи. Третья фича — флоучарт главы в стиле Detroit: Become Human — та же
самая информация, только нарисованная: узлы-сцены, развилки, концовки,
непройденное скрыто под «???».

Все три отвечают на один вопрос: **как устроен граф истории и где в нём игрок**.
Референс отвечает на него тремя независимыми рукописными структурами, и цена
этого видна в его же коде:

| Референс | Цена |
|---|---|
| Подсказки привязаны к **тексту** пункта меню (`startswith` по подписи) | Правка формулировки или перевода молча отвязывает гайд; в их же файлах есть живой пример расхождения |
| Конфликты веток — рукописный список пар множеств id (6 групп) | При росте каталога не сопровождается; ошибка не обнаруживается ничем |
| Прекондиции реплея — ручной пин переменных в начале метки плюс россыпь `or _in_replay` по сюжету | Забытый флаг = `NameError` у игрока; проверки нет |
| Валидация данных гайда — regex-скан шести захардкоженных файлов в dev-режиме | В проде рассинхрон не виден вовсе |

Копировать это нельзя: у нас есть то, чего у референса нет — статически
известный граф (`exits` + `when`), Variable Registry, стабильные id выборов и
build-time валидация. Ровно на этом фундаменте фичи выходят дешевле и надёжнее
оригинала.

## Решение

**Единственный источник правды — скомпилированный граф истории.** Флоучарт,
walkthrough и реплей — три проекции одного артефакта; руками не ведётся ничего.

### 1. Модель и артефакт

Новая стадия компилятора (`tools/vn/src/vn/content/flow.py`) собирает модель из
двух источников, уже существующих в конвейере:

- **декларации** — `graph.build_edges()` (сцены, `exits`, `when`, цели) плюс
  `vars@1` (типы, значения по умолчанию);
- **AST авторских сцен** — build-bridge, расширенный до пер-пунктовых данных
  меню (какой пункт какой `exit` возвращает и что пишет).

Выход — детерминированный (сортировка на каждом уровне) артефакт:
`game/generated/registry/flow.gen.rpy` для рантайма и тот же документ в JSON для
диффа и ревью (`vn content flow --json`). В артефакте: узлы сцен, узлы-развилки
с адресацией `(menu_id, idx)`, рёбра с условиями, условия достижимости каждой
сцены, пары несовместимых сцен и прекондиции реплея.

### 2. Представление достижимости: конъюнктивные миры над ограниченным подмножеством условий

`when` — выражение, которое рантайм исполняет `py_eval`, то есть в общем случае
это произвольный Python. Понимать его целиком компилятор не может и не будет.
Решение: **документированное подмножество**, всё остальное — «непрозрачное»
условие.

- Поддержано: `var`, `not var`, `var == литерал`, `var != литерал`,
  `var >= N`, `var > N`, `var <= N`, `var < N`, `and`, `or`, скобки.
- Ограничение на переменную: для `bool` — подмножество `{False, True}`; для
  `str` — множество разрешённых или запрещённых литералов; для `int`/`float` —
  интервал; для `list`/`dict` — только пустота/непустота.
- **Мир** — конъюнкция ограничений по переменным; достижимость сцены —
  дизъюнкция миров, посчитанная прямым распространением от входной сцены главы.
- Условие вне подмножества делает ребро непрозрачным: сцена считается
  достижимой, но ограничений из него не извлекается (плюс предупреждение
  сборки). Это честная сторона ошибки: см. §3.

Отвергнуто: BDD/SAT-солвер. Домены здесь крошечные (булевы флаги, единицы
литералов, пороги), а цена — внешняя зависимость и непредсказуемое время;
интервалы с подмножествами дают тот же ответ на реальных данных и читаются
в диффе артефакта глазами.

Бюджет: цель — компиляция графа на 500 сцен в единицы секунд. Число миров на
сцену ограничено (`FLOW_MAX_WORLDS`), при переполнении лишние ограничения
ослабляются (widening) с предупреждением; иначе комбинаторика на слиянии
ветвей растёт экспоненциально.

### 3. Сторона ошибки выбрана осознанно

Достижимость считается **сверху** (over-approximation): порядок прохождения
сцен внутри мира не моделируется. Следствие: «совместимы» может быть сказано
там, где путей на самом деле нет, но «несовместимы» — только когда ограничения
действительно противоречат.

Это правильная сторона для UI: красным (недостижимо в одном прохождении)
помечается лишь доказанный конфликт. Ложное «красное» было бы прямым обманом
игрока; ложное «зелёное» приведёт к пересчёту плана по ходу, который в фиче
и так предусмотрен.

### 4. Подсказки — по стабильным id, не по тексту

Пункт меню адресуется парой `(menu_id, idx)` (C1). Опора надёжна: условные
пункты меню — ошибка компиляции (`content/scenes.py`), поэтому набор пунктов
не фильтруется в рантайме и индексы не съезжают. Текст подсказки собирается
из данных графа (какая цель, какое ограничение закрывается), а не пишется
руками; подписи пунктов берутся из леджера, то есть переводятся штатно.

### 5. Прекондиции реплея выводятся, а не пишутся

Для каждой сцены: переменные, которые она читает (декларация `vars.reads` плюс
факт из AST), пересекаются с мирами достижимости; из каждого мира берётся
детерминированный представитель значений. Так на сцену получается один или
несколько «классов состояния» — их и предлагает игроку просмотрщик («как в
прохождении, где …»). Отсутствие значения (переменная читается, но никем не
пишется и без `default`) — ошибка сборки, а не сюрприз в рантайме.

Реплей играет в песочнице движка (`renpy.call_replay`): сторы изолируются
`StoreBackup`, контекст и rollback-лог создаются заново, сохранение выключено.
Состояние входа передаётся движку как `scope` — он пишет переменные сторов по
путям вида `ch01.met_mira` уже ПОСЛЕ `clean_stores()` и `default`-ов (SDK
`renpy/game.py: call_replay`), поэтому своего кода расстановки состояния у нас
нет и быть не должно: он работал бы до инициализации сторов.

Изоляции **persistent** движок не даёт, поэтому реплей гейтит наши побочные
эффекты двумя способами: прогресс главы, достижения и разблокировку галереи
глушит `vn.in_replay()` внутри `vn.checkpoint`, а показанные кадры — наш
`config.no_replay_seen = True` (по умолчанию движок считает кадры реплея
увиденными, то есть пересмотр открывал бы галерею заново).

Имя фичи в коде — **revisit**, не replay: `replay@1`, `vn test replay` и
`ci/fixtures/replays/` уже заняты QA-механизмом записи прогонов, и путаница
этих двух вещей зафиксирована ещё в ADR-0010.

### 6. Тестовый контент — пак вне флейворов

Топологии, на которых фичи проверяются (сходящиеся ветви, взаимоисключающие
концовки, гейты по переменным, пропускаемые сцены), живут в `packs/qa_flow/`.
Пак не перечислен ни в одном `flavors.packs`, поэтому в релизе
`vn.pack_registry.installed()` возвращает False и контент не виден; в dev и CI
он играбелен. Это и есть «один переключатель»: строка в `project.yaml`.

`chapter.status` для этого не годится — гейт зрелости релиза обходит все главы
дерева и красит `draft`/`playtest` независимо от флейвора. Заявленный в
`ARCHITECTURE.md §1.7` механизм `flags@1` («выключенный контент не существует в
release-сборке») в коде отсутствует полностью, и заводить его ради тестовых
глав — отдельная работа с собственным ADR.

## Последствия

- Три фичи получают один контракт и одну точку валидации: расхождение данных с
  сюжетом невозможно по построению, а не отлавливается регексом в dev-режиме.
- Появляется новая обязанность у автора сцены: `when` вне поддержанного
  подмножества даёт предупреждение сборки. Это цена статических гарантий.
- Мост (`050_build_bridge.rpy`) расширяется пер-пунктовыми данными меню и
  литеральными присваиваниями. Кэш анализа инвалидируется сам: его ключ
  включает байты моста.
- Сбор `chNN`-переменных переводится на `chapter_zones()` — иначе глава пака
  (в том числе тестовая) не может объявить своих переменных. Расхождение с
  докстрингом самого хелпера («раньше раскладка была скопирована в четыре
  места») закрывается.
- Состояние игрока (что видено, какие цели отмечены, включён ли гайд) живёт в
  трёх плоских `persistent.vn_story_seen` / `vn_story_targets` / `vn_guide`
  (C9) и **не** трогает `save_schema`: миграций, новых фикстур сейв-корпуса и
  линии `.rpyc` это не требует. `vars@1` здесь не используется намеренно —
  документ описывает переменные СЮЖЕТА, а это состояние интерфейса.
- **Переменные тестового пака в сборку игрока не уезжают** (RTL-046, CLOSED).
  Первая редакция этого ADR утверждала обратное: генерат один на все флейворы
  (иначе рвётся линия `.rpyc`, G6), поэтому `default ch70.path = 'none'` и его
  соседи исполнялись бы в любой сборке, а Ren'Py кладёт в сейв любую изменённую
  переменную стора. Решение нашлось дешевле флейвор-зависимого генерата:
  объявления паков ВНЕ всех флейворов выделены компилятором в отдельный файл
  `state/defaults_unshipped.gen.rpy`, который исключается из дистрибутива глобом
  `build_info.exclude` (`release.py: unshipped_exclude_globs`) — в dev-чекауте
  файл есть и тестовые главы играбельны, в сборке его нет. Скомпилированные
  СЦЕНЫ таких паков из генерата не исключаются намеренно: линия `.rpyc` одна на
  все флейворы, а видимость контента гейтит `pack_registry.installed()`.
  `save_schema` и снапшот миграций при этом не затрагиваются вовсе —
  `_emit_snapshot` тестовые сторы не видит. Держат это два теста:
  `test_release.py::test_unshipped_pack_vars_are_excluded_from_every_flavor` и
  `test_scene_pipeline.py::test_unshipped_pack_vars_are_split_out_of_the_shipped_generat`.
- Автопилот получает вход в главу мимо `Start()` (`VN_AUTOPILOT_CHAPTER`) — тем
  же способом, каким это делает игрок с карточки главы (`Start(entry_label)` =
  `renpy.jump_out_of_context`). Без него покрытие ветвления не может быть полным
  ни для одного эпизода или DLC: `Start()` ведёт только в первую главу реестра.
  Список глав, которым нужна своя трасса, `vn test paths` берёт из графа
  (корневая = в неё не ведёт ни одно ребро), а не из своего представления о
  структуре игры.
- Тестовый контент попадает в леджер локализации. Контент, который не уезжает
  ни одному игроку, не должен участвовать в покрытии переводов, поэтому главы
  паков вне флейворов исключаются из знаменателя покрытия. Мета-строки самого
  пака (его заголовок, заголовки глав, подписи кластеров) живут в общем
  `content/ui/strings.yaml` — своей зоны UI-строк у пака нет — и потому всё-таки
  переводятся: 7 коротких строк дешевле, чем механизм пер-паковых леджеров.
- Флоучарт раскладывается автоматически (слоевой алгоритм по графу); ручные
  координаты не появляются. Декларация главы получает необязательные кластеры
  (фазы) — только для группировки, не для геометрии.
- Зум карты — один `Transform` над всем полотном, а не умножение каждого
  размера на коэффициент. Следствие: панели-фоны (ADR-0009) рендерятся в свою
  полную геометрию и не сплющиваются ни на каком масштабе, а в раскладке не
  остаётся ни одного `* zoom`. Плата — текст на мелком масштабе масштабируется
  растром, а не рендерится в мелком кегле.
- `title_key` сцены перестаёт быть косметикой: без него игрок увидит на карте и
  в подсказке гайда её id (`ch01_s020`). Поставляемым главам заголовки
  добавлены; у тестовых паков откат к id оставлен намеренно — там id
  информативнее выдуманного названия.
- Пространства ключей UI: `ui.chart.*` — карта главы и цели, `ui.guide.*` —
  подсказки в точке выбора. Уже занятое `ui.flow.*` — служебные сообщения
  ПОТОКА сцен (`030_flow.rpy`), и складывать туда карту значило бы путать две
  разные вещи в одном префиксе.
- Гайд выключен по умолчанию (`persistent.vn_guide = False`) и включается в
  настройках. Подсветка «правильного» пункта на первом прохождении отнимает у
  выбора смысл, поэтому фича не должна включаться сама.

## Бюджет масштаба

Замер на 500 сценах (10 глав × 50, развилка через каждые две сцены — слияния
единственное место, где миры размножаются произведением): модель считается за
**~7 с** (разбор деклараций 0.9 + достижимость 5.9 + матрица конфликтов 0.6 +
прекондиции 0.01). Первая рабочая версия давала на том же входе 39 с; всё время
уходило в поглощение миров, где сравнение ограничений шло через `as_data()`, то
есть с сортировкой множества на каждую пару. Гейт — `test_flow.py::
test_five_hundred_scenes_stay_in_seconds`, потолок 18 с: он обязан ловить смену
класса сложности, а не дрожание раннера.

## Проверки

- `vn content flow` — build-time гейт в `ci.yml` (после `vn build`: кэш анализа
  тёплый, движок второй раз не поднимается). Без `--json` печатает сводку, с
  `--json` или с `--out` — детерминированный артефакт для диффа.
- `vn test revisit` — ночной гейт: движок реально проигрывает КАЖДОЕ состояние
  входа из графа (26 сцен → 36 вариантов на текущем дереве). Прекондиция это
  обещание про рантайм, и сдержать его может только рантайм.
- `flow@1: complete` означает «AST разобран у каждой объявленной сцены», а не
  «аргумент analyses передан»: на дереве без авторских `.rpy` модель обязана
  назвать себя неполной, иначе на флаге нельзя строить подсказки.
