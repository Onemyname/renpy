# ADR-0020: CI отключён; гейты локально, релизы вручную

- **Статус:** принято
- **Дата:** 2026-08-21
- **Затрагивает нормы:** раздел 7 ARCHITECTURE.md (CI-конвейер, релизный процесс), G6 (носитель `.rpyc`-линии), G18 (canary)

## Контекст

Минуты GitHub Actions исчерпаны (август 2026), оплачивать их владелец не готов.
Все пять workflow (`ci`, `nightly`, `canary`, `release`, `steam-upload`) переведены
в `disabled_manually` — до этого каждый пуш и каждая ночь давали мгновенно-красный
прогон по биллингу, неотличимый в списке от настоящей поломки. Релиз v1.0.0
(2026-08-20) собран и опубликован вручную с локальной Windows-машины.

Модель качества проекта («валидация до мержа», раздел 7) опиралась на CI как на
исполнителя. Исполнителя больше нет; сами гейты — код `vn` — никуда не делись и
работают локально, включая движковые прогоны (smoke на Windows идёт без xvfb).

## Решение

1. **Workflow-файлы остаются в репозитории**, но отключены на стороне GitHub.
   Файлы поддерживаются в честном состоянии (не описывают того, чего нет), чтобы
   включение обратно было переключателем, а не археологией.
2. **Гейт перед пушем — локальный git-hook** `ci/hooks/pre-push` (быстрый
   `vn content lint` + сохранённый вызов git-lfs). Установка: `sh ci/hooks/install.sh`.
   Hook версионируется в `ci/hooks/`, потому что `.git/hooks` не в git.
3. **Полный гейт — руками перед тегом**: `vn release validate --flavor public|patron`
   плюс pytest и движковый lint. Пошагово — `docs/runbooks/manual-release.md`.
4. **Релизы собираются и публикуются вручную** по тому же runbook: сборка обоих
   флейворов пиннованным SDK, аплоад через GitHub REST API.
5. **Носитель `.rpyc`-линии (G6) — git** (`ci/rpyc-cache/<флейвор>/<версия>/`),
   а не кэш Actions: кэш недоступен и истекает, а копия в gitignored `build/`
   жила бы ровно до `rm -rf build`.

## Что осознанно потеряно

- **Canary (G18)**: дрейф свежего Ren'Py против пина 8.5.3 не отслеживается.
  Расхождения всплывут скопом в момент вынужденного апгрейда SDK — принято.
- **Ночная матрица** (smoke по веткам × языкам, корпус сейвов, controller-профили,
  релизный dry-run): автоматического расписания нет. Компенсация — прогон полного
  набора перед каждым тегом (runbook) и по желанию перед крупными мержами.
- **Гейт на каждый пуш** сужен до lint в pre-push: полный `vn build` + pytest на
  каждый пуш локально стоили бы минуты и провоцировали бы `--no-verify`.

## Сопутствующие решения

- **Хранилище сырцов**: при текущем объёме основной носитель — git LFS;
  внешнее хранилище (`.vnstorage.yaml`) не используется, его гейт сообщает об
  этом явно, а не вакуумным PASS. Триггер пересмотра: первый сырец > 100 МБ
  (PSD/DAZ-сцена) → завести внешнее хранилище и вернуть гейт в строгий режим.
- **Patron-артефакты в GitHub Releases**: допустимо, ПОКА репозиторий приватный.
  Перед любой сменой видимости на public — сначала удалить patron-ассеты из
  релизов (runbook, предохранитель у шага аплоуда).
- **Steam-ветка настроена на плейсхолдерах** (2026-08-21, заморозка снята):
  App ID 480 / депоты 481–483 / DLC 484–485 — тестовые номера, конвейер VDF и
  раскладки депотов прогнан целиком. Перед реальной выкладкой номера меняются
  на выданные Steamworks (см. ci/steam/README.md).
- **Черновая TTS-озвучка принята как релизное качество 1.0.0** — явным списком
  принятых дублей, а не молчанием (см. `vn voice validate`); новые драфты
  по-прежнему дают WARN.

## Последствия

Проще: нулевая стоимость инфраструктуры; релиз воспроизводим на одной машине.
Дороже: дисциплина держится на runbook и hook'е, а не на сервере; ночные
регрессии ловятся с задержкой до ближайшего ручного прогона. План отступления:
оплатить минуты или перейти на self-hosted runner — workflow-файлы остаются
рабочими, включение обратно = кнопка «Enable workflow» на каждом из пяти.
