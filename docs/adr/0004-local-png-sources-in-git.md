# ADR-0004: PNG-слои как открытый промежуточный формат; демо-сырцы временно в git

- **Статус:** принято
- **Дата:** 2026-08-07
- **Затрагивает нормы:** G2, G12, G13, раздел 2

## Контекст

Фаза 1 ассет-конвейера. Боевой путь художника — PSD, но (а) реальных PSD ещё нет,
(б) экспортированные слои и так объявлены архитектурой самостоятельным «открытым
промежуточным форматом» (G12: сборка дистрибутива не должна требовать проприетарных
инструментов). S3-хранилище сырцов ещё не развёрнуто (endpoint'ы в .vnstorage.yaml —
плейсхолдеры).

## Решение

1. Канонический промежуточный формат — **PNG-дерево** `assets_src/png/…` (конвенция —
   docstring `tools/vn/src/vn/assets/pipeline.py`). PSD нарезается конвейером в ту же
   конвенцию (staging `.vncache/psd_png/`, НЕ в source-зону), дальше — общие трансформации.
2. **Временно, до развёртывания S3** (фаза 2, `vn assets pull|push|lock`): небольшие
   PNG-сырцы коммитятся в git прямо в `assets_src/png/` (сейчас — только сгенерированное
   демо-искусство, 108 КБ). Порог: суммарно < 50 МБ; при превышении или при появлении
   боевого арта — обязательный переход на хранилище+манифесты (норма G2 восстанавливается).
   Порог **enforced в тулинге**, а не на словах: `vn content lint` (значит и CI, и
   релизный гейт) считает вес бинарей в `assets_src/` и краснит сборку при
   превышении `ADR0004_BINARY_LIMIT_MB`, предупреждая уже на 60% порога.
   Манифесты/декларации/сайдкары бинарями не считаются — им место в git.
3. `vn content lint --layout` НЕ считает PNG в assets_src нарушением до закрытия этого ADR.

## Последствия

- Клятва «в git только манифесты» для assets_src временно ослаблена — осознанно и
  с материальным порогом; закрытие ADR — часть задачи развёртывания S3.
- Художники уже сейчас могут работать «мимо PSD» ручным экспортом слоёв — конвейеру
  всё равно, откуда пришло PNG-дерево.
