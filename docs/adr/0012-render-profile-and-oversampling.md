# ADR-0012: Render-профиль, оверсэмпл-варианты и модель памяти образов

- **Статус:** принято
- **Дата:** 2026-08-09
- **Затрагивает нормы:** G2 (зона мастеров переименована в `assets_src/art/`), G13 (параметры трансформации входят в ключ кэша), G16 (расширение `project@1`, `assets_manifest@1`, `location@1`), G19 (пересмотр размерных бюджетов, новый бюджет памяти сцены), ADR-0004 (порог бинарей считается только мимо LFS), ADR-0006 (видео получает оверсэмпл-варианты).

## Контекст

Аудит готовности конвейера к приёму production-графики вскрыл, что четыре решения,
выглядевшие как технические ограничения, были непроверенными умолчаниями:

1. **«Только PNG».** Мастер отличного от PNG формата не отвергался, а **молча
   исчезал**: discovery ходил `glob("*.png")`. JPEG-мастер фона, лишний уровень
   вложенности, опечатка в имени папки — всё это пропадало без единого сообщения
   и всплывало чёрным экраном в игре.
2. **«Только 1920×1080».** Разрешение не проверялось **вообще** (`grep` по
   `width|height|resolution` в конвейере давал ноль совпадений), а сцены
   показывают образы 1:1 в виртуальных пикселях. Мастер другого размера тихо
   вылезал за экран или оставлял поля.
3. **Суффикс `@2` был вшит в имя выхода спрайта.** Ren'Py включает автоподбор
   варианта повышенного разрешения **только для имени без собственного `@N`**
   (`renpy/display/im.py`: `get_oversampled_image`). Захардкоженный `@2` этот
   механизм отключал: игрок на 1080p грузил вчетверо более тяжёлую текстуру, чем
   способен увидеть, а игрок на 4K не получал ничего сверх неё.
4. **`config.image_cache_size_mb` не задавался нигде.** Потолок памяти сцены был
   дефолтом SDK (400), то есть случайным числом, а не решением проекта. При
   переполнении Ren'Py не падает — он перестаёт предзагружать и начинает
   перерасшифровывать образы посреди сцены: игрок видит фризы, сборка зелёная.

Плюс размерные бюджеты (`assets_total_mb: 500`) были откалиброваны под 20
плейсхолдеров и читались как потолок игры, хотя игра поставляется автономным
билдом без докачки, а 8–15 ГБ — норма жанра.

## Решение

### 1. Render-профиль как данные

`project.yaml: render` (схема `project@1`, реализация `assets/render_config.py`) —
единственное место, где принимаются решения о разрешениях, форматах, прозрачности
и наборе отгружаемых масштабов. Конвейер это исполняет.

Виртуальная сетка (`screen`) отделена от качества ассетов: она остаётся 1920×1080
навсегда, потому что в ней записан весь UI (11 мест с зашитыми координатами в
`game/framework/20_ui` и `gui.rpy`), а качество задаётся `variants`.

### 2. Референсный вариант — без суффикса

Наименьший отгружаемый масштаб пишется под именем без `@N`, крупные — рядом как
`@2`/`@4`. Эмиттеры образов ссылаются **только** на референсный вариант; подстановку
крупного делает движок по физическому размеру экрана
(`config.automatic_oversampling`, зафиксирован в генерате явно).

Следствия: 1080p-игрок грузит вчетверо меньше текстур, чем раньше; 4K-игрок
получает настоящий 4K; включение 4K — это `variants: [1]` → `[1, 2]` и пересборка,
без единой правки сцен, локаций, галереи или character.yaml.

Проверяется не нашим кодом, а движком: `vn test oversample` зовёт настоящий
`Image.get_oversampled_image()` на настоящем дереве `game/assets` (команда
`vn_oversample` в `framework/90_debug`, в релиз не попадает). Джоба в CI.

### 3. Форматы — по назначению, а не по вкусу

| Класс | Мастера | Альфа | Выход |
|---|---|---|---|
| `spr` | png, webp, tif, tiff | **обязательна** | webp RGBA |
| `bg`, `cg` | png, **jpg/jpeg**, webp, tif, tiff | запрещена (отбрасывается) | webp RGB |
| `mov` | mp4, mov, mkv, webm, m4v, avi | — | webm/VP9 |

JPEG разрешён там, где прозрачности нет: запрет «просто потому что PNG лучше» был
искусственным, а фотореалистичный рендер часто приезжает именно JPEG. Для спрайтов
JPEG исключён не вкусом, а отсутствием альфа-канала.

Выход остаётся WebP: он даёт лучший размер при равном качестве, умеет альфу и
грузится Ren'Py на всех платформах. `out_format` конфигурируем на случай, если
скорость декодирования когда-нибудь перевесит размер.

### 4. Никаких тихих потерь

Любой файл в зоне мастеров, не подобранный ни одной веткой конвейера, — **ошибка
сборки**. Валидируются формат, минимальный размер, пропорции, прозрачность и
единство холста слоёв позы. Поле `canvas` в `character.yaml`, годами бывшее мёртвой
поверхностью схемы, стало контрактом: холст — единственное, что связывает слои
позы (layeredimage кладёт их в `(0,0)`).

### 5. Модель памяти вместо догадок

`assets/memory.py` повторяет формулы движка дословно: лимит кэша в **пикселях**
(`mb * 1024 * 1024 // 4`), стоимость образа — **bbox непрозрачного** (+
`expand_texture_bounds`) × 1.34. Обрезка по альфе принципиальна: слой «лицо на
полном холсте» стоит площадь своего bbox, а не холста, и модель без этого завышала
бы сцену в разы.

Worst-case сцены = фон + Σ по участникам (base + тяжелейший наряд + тяжелейшая
эмоция) + запас на UI, считается для **крупнейшего** отгружаемого варианта.
Превышение бюджета — красная сборка (`vn build`), разбор — `vn assets memory`.

### 6. Мастера — в Git LFS

Историю раздувают не бинари, а бинари, попавшие в git объектами: git append-only и
не дельта-сжимает уже сжатые форматы. LFS кладёт в историю указатель ~130 байт.
Локи (G14) у LFS штатные (`git lfs lock`). Отдельная инфраструктура (S3 +
`vn assets push`) для растровых мастеров не нужна и остаётся для не-растровых
гигантов: PSD, Tray-бандлы, `.duf`-сцены, исходники видео.

Порог ADR-0004 теперь считает **только бинари мимо LFS**, а каждый такой файл
называется отдельной ошибкой. Покрытие определяет сам git (`git check-attr`), а не
наш fnmatch: расхождение с правилами `.gitattributes` означало бы ложные ошибки в CI.

### 7. Бюджеты — предохранители, а не потолок

`assets_total_mb: 500 → 20000`, `video_total_mb: 300 → 8000`,
`video_file_mb: 40 → 512`, `generated_total_kb: 2048 → 65536`. Игра остаётся
автономным билдом: без интернета, без докачки, без launcher'а — все ассеты внутри
дистрибутива. Бюджеты ловят аварию (зацикленный экспорт, забытый вариант), а не
ограничивают проект.

### 8. Зона мастеров — `assets_src/art/`

Имя `assets_src/png/` описывало ограничение, которого больше нет. Старый путь
продолжает работать как алиас, чтобы работа художника не ломалась на переходе.

## Последствия

- Художник может отдавать 4K-мастера с первого дня, пока игра отгружает 1080p;
  переход на 4K — правка конфига, а не пересборка контента.
- Все виды тихих потерь ассетов стали ошибками сборки.
- Появился второй потолок производства (память сцены), измеримый и проверяемый;
  раньше он существовал, но был невидим.
- Стоимость: варианты увеличивают вес `game/assets` примерно на 25 % для спрайтов
  и вчетверо для 4K-фонов. Это осознанно оплачено бюджетами.
- План отступления: `variants: [1]` у всех классов возвращает поведение «один
  масштаб», `@N`-выходы вычищаются штатной orphan-очисткой по диффу манифеста.

## Уточнено 2026-08-18: класс `ui` (9-patch панели ADR-0009)

К классам render-профиля добавлен `ui` — набор масштабов генерируемых UI-панелей.
Решение ADR-0012 («варианты — данные профиля, а не константы кода») не меняется,
расширяется только область его действия.

| | классы с мастером (`spr`, `bg`, `cg`, `shot`) | `mov` | **`ui`** |
|---|---|---|---|
| источник | растровый файл в `assets_src/` | видео-сырец | **декларация** `content/ui/panels.yaml` |
| откуда геометрия варианта | `screen`/`master` × масштаб | `heights` | пиксельные поля декларации × масштаб |
| апскейл | запрещён — вариант пропускается (`skipped_variants`) | н/д | **не бывает**: источник не картинка, крупный вариант просто рисуется |
| выход | `<...>[@N].webp` | `<...>[@N].webm` | `ui/<id>[@N].webp` |

Два факта движка, от которых зависит корректность (проверены по SDK 8.5.3):

1. **`Frame` работает с `@N` без правок вёрстки, но `Borders` обязаны остаться
   виртуальными.** `im.py: Cache._make_render` делит размер `Render` на
   oversample; `imagelike.py: Frame.render` считает поля от того же виртуального
   размера (`xborder = min(bw, sw - 2, dw)`); changelog 8.2 — «treated as if it
   was smaller by the oversampling factor … for the purpose of layout». Поэтому
   образ ссылается на безсуффиксное имя, а `Borders` не масштабируются.
2. **На 4K девять кусков панели режутся clipping-блитами, а не сабсёрфейсами.**
   `render.pyx: Render.subsurface` при масштабной `reverse`-матрице уходит в
   ветку «This doesn't actually make a subsurface…»; текстура при этом остаётся
   полного разрешения (`im.py: ensure_bounds_divide_evenly` специально выравнивает
   кроп оверсэмпленных текстур). Чуть дороже по GPU, не блокер.

**Оверсэмпл включается только при `draw_per_virt > 1.0`** (`im.py:
Image.get_oversampled_image` начинается с `if draw_per_virt <= 1.0: return self`).
На Steam Deck (1280×800 против виртуальных 1920×1080, `draw_per_virt ≈ 0.667`)
движок остаётся на 1×, поэтому мерцание 1px-обводки там — артефакт **минификации**,
и `@2` его не лечит. Лечение (толще обводка в декларации либо рендер UI в
физическом разрешении) — **отдельное решение, здесь не принятое**.

**Остаток:** набор масштабов класса `ui` живёт только в `render_config.DEFAULTS` —
`render.classes.propertyNames.pattern` в `tools/schemas/project@1.schema.json`
перечисляет `^(spr|bg|cg|mov|shot)$` и класс `ui` отвергает. Сборка корректна
(боевой `project.yaml` набор не переопределяет), но переопределить его профилем
сегодня нельзя.
