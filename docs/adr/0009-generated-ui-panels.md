# ADR-0009: UI-панели генерируются конвейером из деклараций

- **Статус:** принято
- **Дата:** 2026-08-08
- **Затрагивает нормы:** G13 (новая трансформация `ui_panel`), G2 (`game/assets/ui/` — производная зона), раздел 2 (конвейер ассетов), раздел 4 (UI)

## Контекст

Ren'Py не умеет рисовать скруглённые углы, мягкие тени и обводки на `Solid` —
для этого нужна картинка (`Frame` + `Borders`). Патч «Новый UI» объявил токены
`gui.radius_*`, но применить их не смог и честно зафиксировал это отступлением:
углы остались прямыми, и именно они читаются как «допотопный» вид.

Очевидный путь — нарисовать 9-patch PNG в редакторе — плох на дистанции:

- бинарь в git на каждую поверхность, перерисовка при любой правке палитры;
- вид расходится с токенами `gui.rpy` (два источника истины);
- дизайнер не может изменить радиус без графического редактора и коммита бинаря.

## Решение

Панели **объявляются** в `content/ui/panels.yaml` (schema `ui_panels@1`) и
**рисуются конвейером**: радиус, заливка (сплошная или вертикальный градиент),
обводка, мягкая тень. Выход — `game/assets/ui/<id>.webp` (lossless, производная
зона, не в git) плюс сгенерированные `Frame`-образы
`registry/ui_frames.gen.rpy`.

```
content/ui/panels.yaml -> ui_panel@1 -> game/assets/ui/<id>.webp
                                     -> define vn_frame_<id> = Frame(..., Borders(...))
```

- **Трансформация `ui_panel@1`** живёт в общем контентно-адресуемом кэше (G13),
  но ключ считается **по параметрам конкретной панели**, а не по файлу
  деклараций: правка одной панели не перерисовывает остальные.
- **Вёрстка не знает про пиксели**: в стилях `background vn_frame_choice`.
  Ни путей, ни размеров, ни `Borders` в экранах.
- **Lossless WebP**: 9-patch растягивается движком, артефакты сжатия поехали бы
  по краям. Файлы всё равно крошечные (сотни байт — единицы КБ).

### Геометрия и её ловушка

`Borders = radius + max(blur + |dy|, border.width)`, а элемент **не может быть
меньше `2*Borders`** — иначе движок сжимает фон и вёрстка «сплющивается». Это
поймано на практике: тень `blur: 18` у кнопки выбора дала `Borders(38)`, то есть
минимум 76px по высоте — выше самой кнопки, и кнопки превратились в тонкие
пилюли. Поэтому:

- эмиттер печатает минимальный размер каждой панели в генерат;
- декларация несёт предупреждение о правиле;
- тест держит кнопочные панели в пределах 60px минимума.

## Последствия

- Скругления/тени доступны всему UI сразу, без единого бинаря в git; смена
  палитры — правка YAML и `vn build`.
- Дизайнер работает в текстовой декларации, а не в редакторе изображений;
  вид гарантированно согласован с тем, что реально в сборке.
- Цена: Pillow становится обязательной зависимостью сборки (она и так была —
  PSD/PNG-ветка), плюс дисциплина «минимум `2*Borders`».
- Тени аппроксимируются гауссовым блюром по слою; для сложных эффектов
  (внутренняя тень, многослойное свечение) декларации не хватит — тогда
  отдельная ветка с рисованными ассетами, но это уже осознанное исключение.
- План отступления: удалить панели из декларации и вернуть `Solid` в стилях —
  ядро сборки не затронуто, ветка аддитивна.

## Уточнено 2026-08-18: панели отгружаются в двух масштабах

Решение ADR-0009 не менялось — источником панели остаётся декларация, бинарей в
git не появилось. Уточняется только состав выхода: набор масштабов панелей стал
частью render-профиля (`render.classes.ui.variants`, сегодня `[1, 2]`, ADR-0012),
и конвейер отгружает `game/assets/ui/<id>.webp` **и** `<id>@2.webp`.

Крупный вариант — не апскейл, а **повторный рендер той же декларации**:
`_scaled_spec` (`tools/vn/src/vn/assets/ui.py`) умножает на масштаб `radius`,
`border.width`, `shadow.blur`, `shadow.dy` и тянущуюся центральную полосу; цвета
не трогаются. Масштаб входит в ключ кэша трансформации — иначе `@2` приехал бы
байт-в-байт из блоба 1×.

**Что при этом обязано остаться неизменным** (иначе на 4K поедет вёрстка):
`emit_frames` ссылается на **безсуффиксное** имя, а `Borders` эмитятся в
**виртуальных** пикселях. Оверсэмпленную картинку движок считает «меньше в N раз
для целей вёрстки» (`renpy/display/im.py: Cache._make_render` делит размер
`Render` на oversample; `imagelike.py: Frame.render` берёт поля от того же
виртуального размера — `xborder = min(bw, sw - 2, dw)`; changelog 8.2 — «treated
as if it was smaller by the oversampling factor … for the purpose of layout»).
Масштабировать `Borders` значило бы удвоить поля вёрстки.

Правило «элемент не меньше `2*Borders`» и все минимумы в генерате считаются от
виртуальных значений и потому не изменились.

Разбор со стороны вёрстки, включая оговорку про Steam Deck (оверсэмпл там не
включается вовсе), — `docs/handbook/42-big-picture.md` §5.4.
