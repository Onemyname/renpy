# ADR-0002: Схемы фазы 0 — валидируемое подмножество; конфликты примеров решаются в пользу профильных разделов

- **Статус:** принято
- **Дата:** 2026-08-07
- **Затрагивает нормы:** G16, C4, C11

## Контекст

Верификация фазы 0 обнаружила, что примеры ARCHITECTURE.md конфликтуют между разделами:
формат `chapter.yaml` в 1.5 (scene_order/entry_scene/owner/requires) против 3.4
(order/unlock/scenes: auto/entry_presets/gallery); `scene.yaml` в 1.5 против 3.5
(mechanics/gallery/ending/entry_point, map-форма exit, голый id музыки);
`character.yaml` против 4.3 (display_name/aliases/animated.prebaked и др.).
Аддендум C1–C24 эти поля не фиксировал. Реестр схем обязан быть единственным источником
(G16) — молчаливая развилка недопустима.

## Решение

1. Фаза 0 реализует **минимальное ядро** каждой схемы (`chapter@1`, `scene@1`, `character@1`,
   `vars@1`) с `additionalProperties: false`: поля, нужные работающему коду фазы 0–1.
   За основу ядра взят формат примеров 1.5; `vars@1` выровнен по канону 6.1
   (`doc`, `range`, `export`, `store: persistent`) уже сейчас.
2. При реализации соответствующих подсистем поля из профильных разделов добавляются
   **новой версией схемы** (`scene@2`, …) с миграцией `vn migrate` одним PR — механизм G16.
   При конфликте примеров канон — **профильный раздел** (3 — сцены/главы, 4 — персонажи,
   6 — состояние), примеры раздела 1.5 в ARCHITECTURE.md подлежат правке при следующей
   редакции документа.
3. `loc/loc.yaml` добавляется в нормативное дерево (дерево 1.2 его не упоминало,
   docs/conventions/folder-layout.md — упоминает; канон — folder-layout.md).

## Последствия

- Первый `chapter.yaml` фазы 1 пишется по схеме `chapter@1` этого репозитория, а не по
  примеру 3.4; расширения (unlock, entry_presets, gallery) приедут как `chapter@2`.
- Правка примеров в ARCHITECTURE.md — отдельная задача редакции документа (не блокирует фазу 1).
