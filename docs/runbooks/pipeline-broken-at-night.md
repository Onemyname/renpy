# Runbook: пайплайн сломан ночью перед релизом

Норма: G20. Владельцы инструментов — см. CODEOWNERS (`/tools/` — минимум два человека).

## Симптом: vn build падает локально у всех

1. `vn doctor` — сначала окружение, не код.
2. Откат тулчейна: `git log tools/vn.lock` → `git revert <bump-commit>` → `pip install -e tools/vn`.
3. Если сломан компилятор, а не lock: последний зелёный генерат лежит артефактом CI-джобы `build`
   (30 дней). Скачайте артефакт и распакуйте в `game/generated/` — игра запускается без локальной
   компиляции. (`vn build --use-artifact <sha>` автоматизирует это с фазы 1.)

## Симптом: CI красный, локально зелёно

1. Диффа окружений быть не должно: CI ставит тот же `pip install -e tools/vn[dev]`.
   Проверьте версию образа python в .gitlab-ci.yml против локальной.
2. `vn content lint` с чистым чекаутом (`git stash -u`) — локальные незакоммиченные файлы
   часто «чинят» сборку невидимо.

## Эскалация

- Владельцы `/tools/`: см. CODEOWNERS. Если оба недоступны — релиз переносится;
  хотфиксы поверх непонятного пайплайна запрещены.
- После инцидента: post-mortem в docs/adr/ если причина — архитектурная норма.
