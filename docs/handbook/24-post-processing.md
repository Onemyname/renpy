# 24. Постобработка 2D

> **Статус подсистемы:** NOT IMPLEMENTED как автоматизация — постобработка целиком живёт **вне** `vn`: ни одной команды, ни одного скрипта, ни одной проверки. Единственный кусок кода на этой границе — PSD-нарезка `../../tools/vn/src/vn/assets/psd.py`: **IMPLEMENTED / UNEXERCISED** (в репозитории ноль `.psd`, ноль тестов на модуль, `.vncache/psd_png/` не существует).
> **Отвечает на вопрос:** «Что я обязан сделать с рендером в редакторе до того, как положу его в `assets_src/`, и чего делать НЕ надо, потому что конвейер сделает сам».

Постобработка — это всё между «Iray закончил считать» и «файл лёг в `assets_src/`»: чистка альфы, кроп под канвас, грейд, ретушь AI-артефактов, склейка слоёв, экспорт. В репозиторий попадает **только результат**. Тулинг проекта про этот этап знает ровно одно: он читает PSD, если вы положите его в `assets_src/psd/characters/`.

## Быстрый ответ

```bash
# 1. Рендер -> редактор -> финальный PNG (sRGB, полный холст, прозрачный фон у спрайтов)
# 2. Кладёте PNG по конвенции (16-assets.md §4) ИЛИ PSD в assets_src/psd/characters/<key>/<key>_<pose>.psd
vn assets build --profile draft   # быстро посмотреть, что получилось
vn assets build                   # full перед коммитом
vn assets validate                # конвенции имён + свежесть
vn build                          # генерат + бюджеты
vn test smoke --picks 0,0         # скриншоты движка в .vncache/smoke/shot*.png — единственный визуальный пруф в проекте
```

Конвейер **сам** делает: PNG→WebP, суффикс `@2`, превью `.thumb.webp` (512 по длинной стороне), UI-панели из декларации, удаление осиротевших выходов. Конвейер **не** делает: кроп, ресайз, поворот, цветокоррекцию, чистку альфа-каймы, апскейл, денойз, проверку размеров. §6 — полный разбор границы.

## 4. PSD-конвенция слоёв — читайте целиком

Модуль: `../../tools/vn/src/vn/assets/psd.py` (126 строк). Вызывается **безусловно в начале каждой не-`check` сборки ассетов** — `pipeline.py:266-268`, `slice_all_psd(root, rep)`.

### 4.1 Что именно ожидает код

```
assets_src/psd/characters/<key>/<key>_<pose>.psd
```

- Имя файла обязано матчить `^(?P<key>[a-z][a-z0-9_]{1,23})_(?P<pose>[a-z][a-z0-9_]*)\.psd$` (`psd.py:25`), и `<key>` обязан совпадать с именем папки (`psd.py:111-115`). Для персонажа `mira` с позой `a` это `assets_src/psd/characters/mira/mira_a.psd`.
- Внутри PSD:

```
mira_a.psd
├── base                  ← ОБЯЗАТЕЛЬНЫЙ пиксельный слой верхнего уровня (не группа!)
├── outfits/  (группа)    ← слой на каждый наряд:  school, casual
├── faces/    (группа)    ← слой на каждую эмоцию: neutral, smile, angry
└── overlays/ (группа)    ← опционально: blush, sweat, …
```

| Правило | Реакция | Код |
|---|---|---|
| нет слоя `base` на верхнем уровне, или `base` — группа | **error**, PSD пропускается целиком | `psd.py:67-69` |
| нет группы `outfits` или `faces` | **warning** | `psd.py:76-77` |
| нет группы `overlays` | молча, это норма | `psd.py:75-78` |
| `outfits`/`faces`/`overlays` есть, но это не группа | **error** | `psd.py:79-81` |
| имя слоя внутри группы не матчит `^[a-z][a-z0-9_]*$` | **error**, слой пропускается | `psd.py:83-87` |
| слой полностью прозрачный | **warning** «пустой арт?» | `psd.py:41-42` |
| PSD не открылся (залочен Photoshop'ом, антивирусом) | **error** без трейсбека | `psd.py:56-59` |

### 4.2 Три поведения, которые удивляют

1. **Видимость слоёв игнорируется намеренно.** Экспортируются **все** слои конвенционных групп независимо от флажка глаза: `pil = layer.composite(layer_filter=lambda l: True)` (`psd.py:38`). Обоснование в докстринге: видимость отражает состояние работы художника, а не состав ассетов. Следствие: **черновой слой, забытый в группе `faces`, уедет в билд как настоящая эмоция.** Мусор держите вне конвенционных групп.
2. **Каждый слой экспортируется на полном холсте PSD**, с сохранением позиции: `Image.new("RGBA", (psd.width, psd.height))` + `paste(pil, (layer.left, layer.top))` (`psd.py:37-40`). Это правильно — полноразмерные слои в Ren'Py бесплатны по памяти благодаря `config.optimize_texture_bounds = True` (https://www.renpy.org/doc/html/config.html), который обрезает текстуру по bbox непрозрачных пикселей.
3. **Нарезка не инкрементальна.** Каждая сборка режет каждый PSD заново; кэшируется только последующий энкод (`psd.py:91-95`, признано в докстринге). На боевых PSD в 0,5–4 ГБ это будет доминировать во времени `vn assets build`.

### 4.3 Куда попадает результат

Staging, **никогда** не в `assets_src/`:

```
.vncache/psd_png/characters/<key>/<pose>/{base.png, outfits/*.png, faces/*.png, overlays/*.png}
```

Каталог позы `rmtree`-ится перед каждой нарезкой (`psd.py:64-65`), staging без соответствующего PSD удаляется (`psd.py:120-126`). Дальше эти PNG подхватывает обычный `_discover` — он читает **два** дерева одной конвенции: `assets_src/png/characters/` и `.vncache/psd_png/characters/` (`pipeline.py:110`).

**Конфликт «PSD и ручной PNG на один выход» — это error**, «два источника претендуют на один выход» (`pipeline.py:289-290`). То есть по каждой позе выбирайте один источник: либо PSD, либо ручной PNG-экспорт.

### 4.4 Согласование с матрицей персонажа

Имена слоёв обязаны совпадать с матрицей в `content/characters/<id>/character.yaml`. Для `mira`:

```yaml
matrix:
  poses: [a]                              # -> файл mira_a.psd
  outfits: [school, casual]               # -> слои в группе outfits/
  emotions: [neutral, smile, angry]       # -> слои в группе faces/
```

Что будет при расхождении: собранный слой, которого нет в матрице, даёт **warning** «`outfits/<name>` вне matrix» (`tools/vn/src/vn/content/images.py:172-177`); заявленная в матрице поза без собранного `base@2.webp` — **error** (`images.py:190`). Группа `overlays` собирается в `game/assets/`, но в `layeredimage` **не эмитится** — компилятор честно предупреждает «сейчас мёртвый груз в дистрибутиве» (`images.py:178-182`). Статус: **PARTIALLY IMPLEMENTED**.

**Про подчёркивания в именах слоёв — важное отличие от общих гайдов.** Универсальный совет для Ren'Py «никогда не ставьте `_` внутри имени атрибута» относится к `layeredimage ... group X: auto`, где `_` — разделитель шаблона (https://www.renpy.org/doc/html/layeredimage.html). **Наш компилятор `auto` не использует**: он эмитит `attribute <name> "assets/spr/…/<name>@2.webp" if_any ["<pose>"]` с явным displayable (`tools/vn/src/vn/content/images.py:219-223`). Поэтому `half_closed` здесь совершенно легален — `SLUG_RE` его пропускает. Не переносите это правило из туториалов.

### 4.5 Предупреждение перед первым боевым PSD

Механизм **ни разу не работал на реальных данных**: в репозитории ноль `.psd` (`assets_src/psd/{characters,backgrounds,cg,ui}/` содержат только `.gitkeep`), `.vncache/psd_png/` не существует, и **нет ни одного теста, импортирующего `psd.py`**. Первый PSD прогоняйте осторожно:

```bash
# 1. один PSD, одна поза, минимум слоёв
vn assets build --profile draft
# 2. глазами сверить staging ДО энкода
ls -R .vncache/psd_png/characters/
# 3. сверить с эталонным экспортом из Photoshop/Affinity — хотя бы один раз на персонажа
# 4. проверить, что все слои позы одного размера (гейта нет — 22-rendering.md §4)
python -c "from PIL import Image;import glob;[print(Image.open(p).size,p) for p in glob.glob('.vncache/psd_png/characters/**/*.png',recursive=True)]"
```

Известные ограничения кода, о которых надо знать заранее:

- **Обрабатывается только `psd/characters/`.** Каталоги `psd/backgrounds/`, `psd/cg/`, `psd/ui/` существуют, но кода под них нет — **NOT IMPLEMENTED**.
- **`vn build --check` на чистом чекауте покраснеет на PSD.** `slice_all_psd` в режиме `check` пропускается (`pipeline.py:263-268`), `_discover` читает пустой `.vncache/psd_png/` — и все PSD-производные выходы объявляются осиротевшими.
- psd-tools — независимая реализация формата, а не код Adobe. Smart Objects, часть режимов наложения и эффекты слоя не пройдут round-trip.

## 5. Форматы: почему WebP и где нужен lossless

Ren'Py рекомендует четыре растровых формата — **AVIF, WEBP, PNG, JPG** (плюс SVG): https://www.renpy.org/doc/html/displayables.html. AVIF поддерживается с Ren'Py 8.1.

Что реально производит наш конвейер:

| Класс | Формат в билде | Режим | Почему |
|---|---|---|---|
| Спрайты (`spr/**@2.webp`) | WebP | **lossy q95**, `method=4` | компромисс размера и качества; альфа при этом кодируется с `alpha_quality`=100 (умолчание Pillow, код его не переопределяет) |
| Фоны и CG | WebP | lossy q90 | нет альфы, лучший размер/качество/скорость декода |
| Превью галереи | WebP | lossy q80, 512 по длинной стороне | сетка миниатюр не должна декодировать полноразмерные CG |
| UI-панели | WebP | **lossless** | 9-patch тянется движком: артефакты сжатия поехали бы вдоль краёв (обоснование — `../adr/0009-generated-ui-panels.md:38-39`) |
| Видео | WebM/VP9 | CRF 30 | [Генерация видео](21-video-generation.md) |

**Отличие от общих рекомендаций.** Ресёрч советует спрайты в **lossless** WebP ради чистого края альфы; наш конвейер использует **lossy q95** (`pipeline.py:223`). Это осознанный компромисс размера, а не ошибка — но если на краях спрайта появится «чанковость», причина именно здесь, и лечится она бампом качества **вместе с бампом версии трансформации** (`pipeline.py:38-46`).

**AVIF в проекте NOT IMPLEMENTED.** Pillow 12 умеет AVIF нативно, но ветки в `_transform` нет. Прежде чем предлагать переход, учтите: AVIF меньше по размеру, но дороже по декодированию, а Ren'Py декодирует при загрузке — с `config.predict_statements = 32` это риск подтормаживания на переходах у слабых машин. И на web/mobile-таргетах AVIF нужно тестировать отдельно, документация движка про платформы молчит.

**Факт, который переворачивает спор о форматах: формат не экономит VRAM.** По https://www.renpy.org/doc/html/config.html: `config.image_cache_size_mb` = 300, `config.optimize_texture_bounds` = True, `config.cache_surfaces` = False. Каждый закэшированный пиксель внутри bbox стоит 4 байта независимо от того, приехал он из 2-МБ PNG или из 200-КБ WebP. WebP/AVIF покупают **размер дистрибутива и диска** — это реально и важно (разница между 4 ГБ и 1,5 ГБ загрузки для patron-сборки), — но проблема памяти лечится размером холста и гигиеной альфы, а не форматом.

`.rpa`-архивы, кстати, **не пережимают** содержимое, и в проекте они **NOT IMPLEMENTED** (`build.archive` не встречается в `game/`). Выигрыш берётся на энкодере, а не на архиваторе.

## 7. Альфа и ореолы: что здесь реальная проблема, а что миф

**Ren'Py премультиплицирует альфу** — «the red, green, and blue channels are multiplied by the alpha channel» (https://www.renpy.org/doc/html/matrixcolor.html). Значит классический ореол от мусорных RGB в полностью прозрачных пикселях (каноническое объяснение — https://www.adriancourreges.com/blog/2017/05/09/beware-of-transparent-pixels/) **структурно решён за вас**. Не тратьте неделю на alpha-bleeding-тулинг для Ren'Py-спрайтов.

Что остаётся реальным в цепочке DAZ → пост → WebP:

1. **Загрязнение матта на экспорте.** Если рендер лежал на фоне и был вырезан/кейнут, *частично* прозрачные пиксели края несут в себе цвет старого фона. Премультипликация частичную альфу не чинит. Лечится в источнике: рендерить на прозрачном, никогда не кейить.
2. **Апскейлеры убивают альфу.** Модели семейства ESRGAN — RGB-only. Разделяйте, апскейлите RGB и альфу одним и тем же множителем, собирайте обратно.
3. **Квантование альфы при lossy WebP.** `alpha_quality` по умолчанию 100 и в Pillow, и в ImageMagick, и наш код его не понижает. Но если вы прогоняете PNG через свой батч — не понижайте.
4. **Редактор, не разпремультиплицирующий при импорте.** Проверяется один раз тестовым спрайтом с жёстким краем на чёрном и на белом.

**Ловушка `exact` — и почему она у нас безвредна, но опасна для мастеров.** WebP-энкодеры по умолчанию выбрасывают RGB в полностью прозрачных областях ради сжатия (`-exact` выключен: https://developers.google.com/speed/webp/docs/cwebp; то же у Pillow и ImageMagick). Для Ren'Py это ничего не стоит благодаря премультипликации, **но это необратимо**. Отсюда правило: **PNG-мастера хранятся вне `game/`, собранный WebP — write-only, никогда не открывайте его как рабочий файл.**

**Гигиена альфы — это вопрос памяти, а не только вида.** `config.optimize_texture_bounds` обрезает текстуру по bbox непрозрачных пикселей. Один случайный пиксель с alpha=1/255 в углу (типичный подарок денойзера или неаккуратного ластика) полностью выключает эту оптимизацию и возвращает в кэш весь холст. Проверяется одной строкой на Pillow: `Image.open(p).getchannel("A").getbbox()`.

## 10. Чего НЕ делать

- **Не править файлы в `game/assets/`.** Перезапишет ближайшая сборка; хуже — файл, которого нет в манифесте, не удалится никогда и поедет мёртвым грузом в каждый дистрибутив.
- **Не открывать собранный WebP как рабочий файл.** RGB в прозрачных областях выброшен безвозвратно (`exact` по умолчанию выключен). Мастера — PNG/TIFF вне `game/`.
- **Не оставлять черновые слои в группах `outfits`/`faces`/`overlays`.** Видимость игнорируется намеренно (`psd.py:38`) — забытый слой уедет в билд полноценным ассетом.
- **Не держать одну позу и в PSD, и в ручном PNG.** Это error «два источника претендуют на один выход» (`pipeline.py:289-290`).
- **Не полагаться на `psd-tools` без сверки.** Первый PSD каждого персонажа сверьте с эталонным экспортом из Photoshop/Affinity. Эффекты слоя запекайте: экстра `[composite]` в зависимостях **не объявлена**.
- **Не экспортировать слои кропнутыми.** Полный холст обязателен: смещения слоёв никто не хранит, а по памяти полноразмерные слои бесплатны (`optimize_texture_bounds`).
- **Не срезать ICC до конвертации в sRGB** и не путать `magick -colorspace sRGB` (интерпретация) с `magick -profile sRGB.icc` (реальная конвертация).
- **Не переносить правило «никаких `_` в именах атрибутов»** из туториалов по `layeredimage auto` — у нас эмиссия явная (§4.4).
- **Не делать миниатюры и `@2`-копии руками** — это работа конвейера (§6).
- **Не класть QA-артефакты в `game/`** — уедут игроку.
- **Не переименовывать собранный ассет.** Логические id неизменяемы (G7): переименование = новый id + запись в `content/renames.yaml`.
