# 45. Architecture & Development Rules: конвенции и запреты

> **Статус подсистемы:** PARTIALLY IMPLEMENTED — большая часть правил ниже имеет автоматического ловца (`vn content lint` — 33 диагностики, `vn build` — контракт сцен и Variable Registry, 373 pytest-теста, релизный гейт — 21 проверка). Но **часть конвенций держится только на ревью**: префикс `vn_` у экранов/компонентов, «никаких литералов в экранах», запрет `import` в рантайм-python, уровень `init -998` для расширения фасада. Для каждого правила в §16 указано, кто именно его ловит — и где стоит «никто».
> **Отвечает на вопрос:** «Как это назвать, что при этом нельзя, и что сломается, если нарушить?»

Этот файл — свод правил, а не обучение. Он собран **из кода**: каждый regex, путь и запрет ниже проверен по
`tools/vn/src/vn/`, `game/framework/`, `tools/schemas/` и нормам раздела 0
[`docs/ARCHITECTURE.md:36-203`](../ARCHITECTURE.md). Практика «как сделать» — в профильных файлах
хендбука ([02](02-architecture.md), [09](09-chapters.md), [12](12-scenes.md), [16](16-assets.md));
здесь — только «как называется» и «чего нельзя».

## Быстрый ответ

Десять запретов, которые нарушают чаще всего. Полная таблица — §15, карта ловцов — §16.

| Нельзя | Что сломается | Кто поймает |
|---|---|---|
| Править файл с шапкой `AUTO-GENERATED` | Правка исчезнет на следующей сборке; `vn build --check` покраснеет | `vn build --check` (`compile.py:1168-1178`) |
| `git mv` сцене/главе | Сейвы игроков ломаются навсегда (statement-имена в `.rpyc`) | `vn content lint` — только после релиза (`lint.py:383-404`); до релиза **никто** |

| Переменная в сцене без декларации в `*.vars.yaml` | Фантом-стор вне сейва и миграций | `vn build` (`scenes.py:236-243`), error (draft → warning) |

## 2. Naming: файлы и каталоги

Regex — не из документации, а из кода. Одни и те же паттерны дублированы в линтере и компиляторе
намеренно: линтер ругается внятно, компилятор физически не собирает то, что не матчится.

| Сущность | Паттерн | Где в коде | Пример |
|---|---|---|---|
| Папка главы | `^ch(\d{2})_([a-z][a-z0-9_]{2,30})$` | `lint.py:16`, `compile.py:31` (`CHAPTER_DIR_RE`) | `ch01_awakening` |
| Файл сцены (пара) | `^s(\d{3})_([a-z][a-z0-9_]{2,40})\.scene\.(yaml\|rpy)$` | `lint.py:17` (`SCENE_FILE_RE`) | `s020_school_gate.scene.yaml` |
| Файл сцены (компилятор) | `^s(\d{3})_([a-z][a-z0-9_]{2,40})\.scene\.yaml$` | `compile.py:32` (`SCENE_YAML_RE`) | — |
| Декларация шотов | `^(s\d{3})\.shots\.yaml$` | `compile.py:641` (`SHOTS_YAML_RE`) | `shots/s030.shots.yaml` |
| Voice-манифест | `<lang>.voice.yaml`, код языка `^[a-z]{2,3}(_[A-Z]{2})?$` | `voice.py:33-35`, `voice@1.schema.json` | `voice/ru.voice.yaml` |
| Папка персонажа | `^[a-z][a-z0-9_]{1,23}$` | `lint.py:18` (`CHAR_DIR_RE`), `character@1` | `mira` |
| Папка локации | id == имя папки, `^[a-z][a-z0-9_]*$` | `images.py:47-48`, `location@1` | `school_gate` |
| Файл миграции | `^\d{4}_[a-z][a-z0-9_]+\.py$` | `migrations_registry@1`, `_collect_migrations` (`compile.py:474`) | `0002_route_prologue.py` |
| Генерат сцены | `game/generated/scenes/chNN/<full_id>.gen.rpy` | `compile.py:1044` | `scenes/ch01/ch01_s020.gen.rpy` |

**Слуг живёт только в имени файла и папки.** В id, метках и путях генерата его нет — id неизменяем,
слуг менять можно (C3, `naming.md`).

**Номера сцен — с шагом 10** (`s010`, `s020`, …): между ними должно оставаться место для вставки.
Порядок задаёт `chapter.yaml: scene_order`, номер — человекочитаемый якорь, а не сортировочный ключ.

### 2.1. Обязательные и запрещённые пути

Линтер держит два закрытых списка (`lint.py:21-53`):

```python
REQUIRED_DIRS  = game/framework/{00_core,00_core/engine_compat,10_systems,20_ui,90_debug},
                 content/{chapters,characters,registry}, tools/schemas, docs
REQUIRED_FILES = project.yaml, .vnstorage.yaml, content/renames.yaml,
                 content/registry/id_registry.json, content/flags.yaml,
                 content/anchors.yaml, content/migrations/registry.yaml
FORBIDDEN_PATHS = game/content, game/images
```

Комментарий над `REQUIRED_FILES` (`lint.py:34`) формулирует смысл списка прямо: «Инвариант "lint
зелёный ⇒ build не падает" держится на этом списке». `game/images/` запрещён потому, что
автоопределение образов по этому каталогу даёт тихие коллизии имён — все `image` приходят из
`registry/images.gen.rpy` (`images.py:1-2`).

`content/flags.yaml` и `content/anchors.yaml` обязаны существовать, но их содержимое **не читает
никто** — ни компилятор, ни рантайм (см. [02-architecture.md §7](02-architecture.md)). Не принимайте
их существование за работающий механизм.

## 3. Label naming: контракт `__body` / ветки

Норма C2 (`ARCHITECTURE.md:118`), исполнитель — `tools/vn/src/vn/content/scenes.py`.

```
LABEL_RE = ^(?P<scene>ch\d{2}_s\d{3})__[a-z0-9_]+$        # scenes.py:18
```

| Метка | Кто пишет | Правило |
|---|---|---|
| `label ch01_s020:` | **компилятор** (`emit_scene`, `scenes.py:334-338`) | автор её не пишет никогда |
| `label ch01_s020__body:` | автор | обязательна; её отсутствие — error (`scenes.py:173-174`) |
| `label ch01_s020__caught:` | автор | любой суффикс `[a-z0-9_]+`; префикс своей сцены обязателен |
| `label ch01_s020` (shim) | компилятор из `renames.yaml` / `id_registry` | `_emit_overrides` (`compile.py:510-546`) |

Проверка идёт по AST от парсера Ren'Py, не регексом (G24). Каждая метка сцены обязана матчиться
`LABEL_RE` **и** её группа `scene` обязана совпадать с id этой сцены — иначе
`метка … вне контракта ^<full_id>__<suffix>$ (C2; naming.md)` (`scenes.py:166-171`).

**Переходы наружу — только `return "<exit_id>"`.** Прямой `jump`/`call` на метку вне префикса своей
сцены даёт error: `переход вне своей сцены; межсценовые переходы только через return "<exit_id>" +
exits (C2)` (`scenes.py:184-188`). `jump`/`call` с `expression` запрещены вообще — динамическая цель
ломает статический анализ и prediction (`scenes.py:178-182`).

**Стабильное from-имя — часть контракта сейвов.** Обвязка эмитит
`call ch01_s020__body from _call_ch01_s020__body` (`scenes.py:377`): Ren'Py требует стабильные имена
точек возврата, иначе сейв внутри сцены не находит, куда вернуться. Смена номера сцены меняет
from-имя даже при живом `label_overrides`.

### 3.1. Метки framework

`label start`, `label vn_scene_unavailable`, `label vn_end_of_content`, `label after_load` живут в
`00_core/030_flow.rpy:217,232,245` и `00_core/020_state.rpy:83`. Реплики в них — **только**
`vn_loc.t(...)`: литерал в framework-метке не попадает в PO-экстракцию (ледгер собирается только из
сцен) и не переводился бы (`030_flow.rpy:213-215`).

## 4. Variable naming и named stores

Норма C21 (`ARCHITECTURE.md:193`), схема `vars@1`.

```
store: ^(g|ch\d{2}|mech_[a-z0-9_]+|dlc_[a-z0-9_]+|persistent)$      # vars@1.schema.json
имя:   ^[a-z][a-z0-9_]*$                                            # propertyNames
ссылка: ^(g|ch\d{2}|mech_[a-z0-9_]+|dlc_[a-z0-9_]+)\.[a-z][a-z0-9_]*$
```

Последний паттерн — общий для `scene@1`, `shots@1`, `achievements@1`, `gallery@1`, `renames@1`,
`id_registry@1`: всё, что ссылается на переменную, обязано ссылаться в этом виде.

| Стор | Что там живёт | Файл декларации | Факт в репозитории |
|---|---|---|---|
| `g` | Глобальное состояние прохождения | `content/variables/*.vars.yaml` | `g.route`, `g.mira_outfit` |
| `chNN` | Состояние конкретной главы | `content/chapters/chNN_*/vars.yaml` | `ch01.met_mira` |
| `mech_*` | Состояние механики | — | схемой разрешено, **не используется** |
| `dlc_*` | Состояние пака | — | схемой разрешено, **не используется** |
| `persistent` | Межсейвовые данные, префикс `vn_` обязателен (C9) | `content/variables/settings.vars.yaml` | `persistent.vn_quality_cap`, `persistent.vn_ui_scale` |

**Правила, которые ловит код:**

1. `store` файла главы обязан равняться id главы — иначе error
   `store (X) != id главы (chNN)` (`lint.py:348-352`).
2. `persistent`-переменная без префикса `vn_` — **`CompileError`**, а не warning:
   `persistent-переменная 'X' обязана начинаться с vn_ (C9)` (`compile.py:165-169`). Плоская модель:
   dict-корня `persistent.vn` не существует.
3. Любое чтение или запись store-атрибута в сцене сверяется с Variable Registry по фактическому AST:
   незадекларированная переменная — error (для `status: draft` — warning),
   `молчаливый фантом-стор вне сейва/миграций (G5)` (`scenes.py:232-243`).
4. Имя без `_`-префикса — жёсткое требование движка, не стиль: Ren'Py не кладёт в сейв переменные,
   начинающиеся с `_` (G5, `020_state.rpy:6`). Поэтому `vn_save_schema`, `vn_menu`, `vn_scene` — без
   подчёркивания, а служебные `_vn_ap_shot` автопилота — с ним, и в сейв не попадают намеренно.
5. `default: null` легален и означает «не выбрано» (`vars@1.schema.json`): именно так объявлены обе
   persistent-настройки (`since: 2`), и в генерат уходит `default persistent.vn_quality_cap = None`
   (`state/defaults.gen.rpy:20`).

**Типы в сейве — только простые** (`type`: str/int/float/bool/list/dict). Причина не стилистическая:
миграции работают над dict-снапшотом (`state/snapshot.gen.rpy`), а после миграции значения проходят
Revertable-конвертацию — объекты, созданные вне renpy-python, иначе не участвуют в rollback
(`020_state.rpy:51-52`, `engine_compat/000_compat.rpy:19`).

## 5. Screen naming и компоненты

Здесь правило простое, а ловца нет — проверяйте глазами.

| Класс | Имя | Пример | Почему так |
|---|---|---|---|
| Экраны движка | **штатное имя движка**, без префикса | `say`, `input`, `choice`, `navigation`, `main_menu`, `save`, `load`, `preferences`, `confirm`, `notify`, `history`, `gallery`, `_exception` | Ren'Py ищет их по фиксированному имени; переименование = экран не показывается |
| Наши экраны и компоненты | `^vn_[a-z0-9_]+$` | `vn_panel`, `vn_button`, `vn_game_menu`, `vn_save_slot`, `vn_chapter_card`, `vn_quick_menu`, `vn_build_overlay`, `vn_content_unavailable`, `vn_modal_dialog`, `vn_pref_slider`, `vn_gal_cell`, `vn_scrim`, `vn_autopilot` | Конвенция объявлена в `20_ui/components.rpy:1` |
| Генерируемый экран | `chapter_select` | `generated/screens/chapter_select.gen.rpy` | C14: экран выбора глав ровно один |

Фактическая раскладка: 23 объявления `screen` в 9 файлах `20_ui/screens/` + 7 в `20_ui/components.rpy`,
плюс один в генерате — итого 31 (`renpy.sh . lint` печатает 33: плюс два дев-экрана из `90_debug/`).
**Автоматической проверки префикса `vn_` не существует** — грепа по тестам на это нет.

**Все константы оформления — токены `gui.*`.** `game/gui.rpy:1-2` объявляет себя единственным местом
констант: «в экранах — только `gui.*` (никаких магических чисел)». Обещанного «линта магических
чисел» (`components.rpy:2`) в коде нет — grep по `tools/vn/src/` даёт ноль. Косвенно связку ловят два
теста: `test_ui_panels.py:369` (интерфейсные кегли обязаны сидеть на множителе `gui.ui_scale`, а
диалоговые — не сидеть) и `test_ui_panels.py:325` (элемент не меньше `2*Borders` своей панели, прогон
при `ui_scale` 1.0 и 1.4).

**Панель 9-patch выбирается по геометрии элемента.** Восемь панелей в `content/ui/panels.yaml`:
`choice`, `choice_hover`, `choice_chosen`, `chip`, `chip_active`, `panel`, `slot`, `toast`. Ставить
`choice*` (минимум 54–60 px по высоте) на кнопку ниже 40 px нельзя — движок сожмёт фон; ровно ради
этого заведены чипы, и регресс закрыт `test_ui_panels.py:394`. Каждая панель отгружается в двух
масштабах (`<id>.webp` + `<id>@2.webp`, ADR-0012), но `Borders` и минимумы считаются в **виртуальных**
пикселях и от масштаба не зависят — вёрстка про `@N` не знает вовсе.

**Единственное исключение из «только `gui.*`» — экран краха** (`20_ui/screens/crash_screen.rpy`).
Там числовые литералы обязательны: токены `gui.*` объявляются на `init -3/-2`, и падение более раннего
init'а оставило бы `gui` неполным — экран краха упал бы сам, не показав игроку ничего. Поэтому кегли,
приоритеты фокуса, геометрия и визуалы скроллбара там заданы числами, а инвариант «ноль обращений к
`gui.*`» плюс нижняя граница кеглей ≥ 18 проверяются `tools/vn/tests/test_crash_handler.py` (6 тестов).
Расширять это исключение на другие экраны нельзя.

**Скролл-зона без визуалов полосы рисуется пустой.** `viewport`/`vpgrid` со `scrollbars "vertical"`
обязан либо брать `properties vn_scroll_props`, либо задавать `vscrollbar_base_bar`/`thumb`/`xsize`
сам: картинок скроллбара в проекте нет, движковый дефолт полосы пуст, и side-раскладка отдаёт вьюпорту
нулевую площадь. Автоматической проверки нет; дефект реально жил в экране краха (трейсбек не
отображался) и исправлен.

## 6. Image naming: зоны, префиксы и `@N`

Зоны выходов (`game/assets/`) и их семантика:

| Префикс | Что | Кто ссылается | Варианты `@N` |
|---|---|---|---|
| `bg/` | Фоны локаций | `location@1: backgrounds`, `image bg <loc> <variant>` | `[1, 2]` + `.thumb.webp` |
| `cg/` | CG галереи | `gallery@1: asset` | `[1, 2]` + `.thumb.webp` |
| `spr/` | Слои спрайтов + `side/` | `layeredimage <char>`, `image side <char> …` | `[1, 2]` |
| `shots/` | Слои послойных шотов (ADR-0013) | `layeredimage shot_<chNN>_<sNNN>` | `[1, 2]` |
| `mov/` | Видео + `.poster.webp` | `Movie(play=…, image=…)` | `[1]` |
| `ui/` | Генерируемые 9-patch панели (ADR-0009) | `define vn_frame_<id>` | нет |
| `voice/<lang>/<chNN>/` | Дубли `.opus` | `voice vn.voice_path("<line_id>")` | нет |
| `audio/{bgm,amb,sfx}/` | `.ogg` треки (C18) | `define audio.<id>` | нет |

**Ссылка — всегда референсное (безсуффиксное) имя.** Ren'Py включает автоподбор `@2`/`@4` только для
имени без собственного `@N` (`render_config.py:193-196`, `images.py:7-13`). Захардкоженный `@2` в
`location.yaml`, в `layeredimage` или в записи галереи **отключает** автоподбор и заставляет игрока
на 1080p грузить 4K-текстуру. Живой генерат ссылается именно на референс:
`always "assets/spr/mira/a/base.webp"` (`registry/images.gen.rpy:32`).

Что подтверждает работу механизма — единственный честный способ: `vn test oversample --scale 2`
гоняет настоящий `Image.get_oversampled_image()` внутри движка (`90_debug/030_oversample.rpy`). На
этом чекауте: `oversample @2: проверено 22, поднято до варианта 13`.

**Тег `layeredimage` = тег персонажа**, атрибуты — из `matrix:` `character.yaml` (C6). Тег шота —
`shot_<chapter_id>_<scene_short>` (`images.py:78-85`): один тег на сцену. Группа `shot`
эксклюзивна — движок сам снимает предыдущий шот, — а атрибуты слоёв **липкие** и переживают смену
шота: выбранный наряд не сбросится сам.

**Единственные образы вне генерата** перечислены вручную:
`FRAMEWORK_IMAGE_TAGS = {"vn_black"}` (`images.py:59`). Список короткий осознанно — разбирать `.rpy`
регексом запрещено (G24), а гонять build-bridge ради одного служебного имени дороже пользы. Любой
новый `image` в `20_ui/images.rpy` обязан попасть в этот frozenset, иначе сверка ссылок
(`scenes.py:89-121`) объявит его несуществующим.

## 7. Character naming

```
ключ персонажа: ^[a-z][a-z0-9_]{1,23}$        # lint.py:18, character@1, C21
```

Правила:

- Ключ = имя папки `content/characters/<key>/` = поле `id` в `character.yaml`. Расхождение — error
  (`lint.py:344-345`).
- Ключ = тег `layeredimage` = имя `Character(...)` в `registry/characters.gen.rpy`
  (`scenes.py:447-458`). Один ключ — один тег образа (G12).
- Состав спрайтов объявляется **единым** `character.yaml` с блоком `matrix:` (poses/outfits/emotions/
  required/forbidden). Файла `sprites.yaml` не существует (C6).
- Персонажи **не переименовываются**: в `renames@1` секции `characters` нет, а линтер даёт error, если
  выпущенный персонаж исчез: `выпущенный персонаж X исчез (id неизменяемы, G7)` (`lint.py:394-398`).
- Цвет — `^#[0-9a-fA-F]{6}$` (`character@1`); имя — через `_()`, чтобы попасть в перевод
  (`scenes.py:452`).

## 8. Chapter / scene id

| Id | Формат | Откуда берётся |
|---|---|---|
| Глава | `^ch\d{2}$` | префикс имени папки, **не** поле `id:` |
| Сцена (короткий) | `^s\d{3}$` | номер в имени файла |
| Сцена (полный) | `^ch\d{2}_s\d{3}$` | `<chapter_id>_<short_id>` |
| say-id | `^ch\d{2}_s\d{3}_\d{4}$` | `vn loc keys` (`keys.py:23`) |
| id меню | `^ch\d{2}_s\d{3}_m\d{3}$` | `vn loc keys`, маркер `$ vn_menu = "…"` (`keys.py:24`) |

**Поля `id:` в YAML — контрольная сумма, а не источник.** Компилятор выводит id из пути; если поле
задано и расходится — error (`lint.py:211-212,233-234`). Это нарочно: путь виден в `git diff`, а поле
можно забыть поправить.

Формат id меню — ровно `m\d{3}`. `m01` не бывает (C1).

## 9. Локализация: правила, ломающие переводы молча

Норма G8 (`ARCHITECTURE.md:67`), ADR-0005.

1. **say-id дописывает `vn loc keys`, а не человек.** Инструмент правит авторский `*.scene.rpy`
   парсером Ren'Py, после правки перечитывает файл мостом и откатывает при расхождении
   (`keys.py:1-13`). Это единственный инструмент, которому разрешено писать в источник истины.
2. **Id никогда не пересчитывается.** Правка текста реплики не трогает её id — поэтому опечатка не
   теряет перевод и не отвязывает записанный дубль озвучки.
3. **У пункта меню клаузы `id` не существует.** Перевод выборов идёт lookup'ом по choice-id:
   `vn_loc.choice_text(vn_menu, idx, caption)` в кастомном `screen choice` (C1). Отсюда следующий
   пункт.
4. **Условные пункты меню запрещены.** Движок фильтрует их **до** `screen choice`, и перевод по
   runtime-индексу съехал бы на соседние пункты. Компилятор даёт error:
   `условный пункт меню #N (…) — запрещено (ломает перевод по индексу); используйте ветвление сцены`
   (`scenes.py:192-198`).
5. **В экранах нет строковых литералов — только `vn_loc.t(key)`** по ключам
   `content/ui/strings.yaml` (108 ключей). Правило объявлено в `20_ui/screens/core_screens.rpy:3-4`;
   фактически `vn_loc.t(` встречается 82 раза в 79 строках `20_ui/screens/**`.
   **Автоматической проверки нет** — литерал пройдёт зелёным и просто не переведётся. Ловится
   прогоном `vn test smoke --picks 0,0 --lang pseudo` глазами: непереведённая строка останется
   обычным текстом среди псевдолокали. Грубый грep-фильтр — в разделе «Валидация».
6. **Голос привязан к say-id, а не к `config.auto_voice`.** Оператор `voice vn.voice_path("<line_id>")`
   инжектирует компилятор в **копию** сцены (`scenes.py:283-301`), авторский файл не трогается. У
   `auto_voice` id — производная от label и текста, поэтому правка реплики молча отвязала бы дубль.
7. **`game/tl/` — производная зона.** Ручные правки там бессмысленны: `vn build` перегенерирует
   (`cli.py`).

## 10. Python внутри Ren'Py: что можно, а что ломает сейв

Три уровня доступа к Python, и они не взаимозаменяемы.

| Форма | Когда исполняется | Что можно | Что нельзя |
|---|---|---|---|
| `init [prio] python:` | до старта игры | `config.*`, создание store, регистрация каналов, `renpy.arguments.register_command` | ничего, что зависит от сейва или состояния прохождения |
| `init [prio] python in <store>:` | до старта игры | определять функции фасада, константы | создавать store позже, чем его потребитель (см. §10.1) |
| `$ …` / `python:` в сцене | в рантайме, попадает в rollback-лог | присваивания задекларированным переменным, вызовы `vn.*` | **`import`** (см. ниже) |

**Запрет №1: `import` в рантайм-python.** Rollback-лог записал бы модуль в сейв (`module_pickle`).
Правило зафиксировано дважды: в докстринге `vn_qa.autopilot_boot`
(«Вызывается из label main_menu qa-файла ОДНИМ выражением: никаких `import` в рантайм-python —
rollback-лог записал бы модуль в сейв (module_pickle)», `030_flow.rpy:153-155`) и в комментарии
внутри генерируемого автопилот-файла (`cli.py`). Ловца нет — соблюдайте руками. Импорты внутри
**тел функций** сторов легальны: они исполняются в рантайме, но результат остаётся локальным и в
rollback-лог не уходит (`020_state.rpy:52`, `030_flow.rpy:6-7`).

**Запрет №2: side effect в выражении экрана.** Экран переоценивается предикцией и каждым тиком
оверлея, поэтому счётчик в выражении дрейфует. Отсюда автопилот выбирает пункт **таймером**, а не
выражением (`030_flow.rpy:131-133`, `20_ui/screens/choice.rpy:53-54`).

**Запрет №3: возвращать `None` из `Function(...)`, обслуживающего интеракцию.** Интеракция меню
завершается только non-None результатом action; иначе таймер выбирает пункт снова и снова, и прогон
висит до таймаута (`030_flow.rpy:148-150`).

**Запрет №4: недокументированные API движка вне `engine_compat`.** Норма G18: все допущения о
внутренностях Ren'Py — только в `game/framework/00_core/engine_compat/000_compat.rpy`, и каждое обязано
иметь контракт-тест (`tools/vn/tests/test_engine_compat.py`, canary-джоба гоняет их на свежем SDK).

### 10.1. Уровень `init` — жёсткая шкала

Полная фактическая раскладка — [02-architecture.md §5](02-architecture.md). Здесь правила:

- **Диапазон `-999..999` включительно.** `init -1000` движок отвергает: «init priority (-1000) is not
  in the -999 to 999 range» (ADR-0003). Уровней выше 999 не заводить.
- **Расширять фасад `vn.*` — только приоритетом строго больше −999.** Store `vn` создаётся на
  `init -999` в `030_flow.rpy:4`. При равном приоритете Ren'Py упорядочивает файлы по пути, поэтому
  `045_audio.rpy` на −999 иногда исполнился бы раньше и упал бы. Проект решил это уровнем **−998** —
  на нём сидят все три дополнения фасада: `045_audio.rpy:24` (`vn.voice_path`), `095_quality.rpy:20`
  (`vn.quality_cap`/`set_quality_cap`), `20_ui/scale.rpy:46` (`vn.ui_scale_pref`/`set_ui_scale`).
  Скопировать `init -999` из `030_flow.rpy` — самая дорогая ошибка этого раздела: она даёт
  невоспроизводимый «no such store», зависящий от имени файла.
- **`20_ui/scale.rpy` переставлять нельзя.** Порядок: хелпер `init -4` → токены `init offset = -3`
  (`gui.ui_scale`, `gui.overscan_pad`) → `gui.rpy` на `init offset = -2`, который на них умножает
  кегли (`gui.rpy:55-64`). Любая правка приоритета здесь молча даёт масштаб 1.0 без единой ошибки.
- **`registry/images.gen.rpy` намеренно на `init offset = 0`** (`images.py:289`): `image` и
  `layeredimage` и так имеют базовый приоритет 500 внутри движка. Не «исправляйте» на 500.

## 11. State management: что попадает в сейв

| Что | Попадает в сейв | Почему |
|---|---|---|
| `default <store>.<name>` из `vars.yaml` | да | генерируется в `state/defaults.gen.rpy` |
| `vn_save_schema` | да | `default`, единственный счётчик схемы (G5) |
| `vn_menu`, `vn_scene`, `vn_unavailable_reason` | да | `default` без `_`-префикса |
| `define vn_build_save_schema` | нет | `define` — константа сборки |
| `vn_build.*` (флейвор) | нет | не `default`; rollback их не трогает (`060_build_info.rpy:1-4`) |
| `persistent.vn_*` | вне сейва, живёт рядом | межсейвовые данные (C9) |
| `_vn_ap_*` (автопилот) | нет | `_`-префикс |

**Снапшот для миграций** — `state/snapshot.gen.rpy`: `SNAPSHOT_VARS` (пары стор×имя) и
`SNAPSHOT_STORES`. `snapshot()` читает **все** переменные управляемых сторов (retired-переменные
старых сейвов видимы миграциям), `apply` — только объявленные. Одна и та же цепочка исполняется в
игре и, когда появится `vn save migrate`, оффлайн (G5).

**Что читает сейв-json**: `config.save_json_callbacks` кладёт три ключа — `vn_save_schema`,
`vn_version`, `vn_scene` (`001_boot.rpy:31-36`). Именно по ним работает `vn save check` без unpickle.

## 12. Save compatibility и backwards compatibility

Самый дорогой раздел: ошибка здесь ломает сейвы **уже вышедшим игрокам**, и патчем это не
откатывается.

### 12.1. Id неизменяемы навсегда (G7, C16)

Statement-имена в `.rpyc` — единственная опора позиционной save-совместимости Ren'Py. Из этого следуют
четыре **разных** последствия смены id, и они не взаимозаменяемы:

| Что меняется | Что теряется |
|---|---|
| say-id | перевод в `loc/po/**` и `game/tl/**`, привязка записанного дубля озвучки |
| id сцены | метка сцены, from-имя `_call_<full_id>__body` в сейвах, якоря галереи и достижений, запись в `id_registry` |
| логический id ассета | `persistent._seen_images` — уже открытые игроку CG в галерее |
| id элемента галереи | ключ в `persistent.vn_gallery_unlocked` |

**Как переименовать (единственный правильный порядок):**

1. Создать сущность с **новым** id, перенести содержимое. `git mv` — неправильный ответ.
2. Записать соответствие в `content/renames.yaml` (`renames@1`). Секций **пять**:
   `scenes`, `deleted_scenes` (`{fallback:, since:}`), `labels`, `vars`, `assets`.
3. `vn build` сгенерирует `registry/overrides.gen.rpy`:
   `init -100 python: config.label_overrides.update({...})` — именно `update`, чтобы паки могли
   дополнять карту (C12) — **плюс** физические shim-метки `label <old>: $ vn.unwind_call_stack(); jump <new>`
   (`compile.py:524-530`).
4. Старый id **никогда** не переиспользуется под другой смысл.

`config.missing_label` не используется намеренно (G7): вместо динамического перехвата генерируются
физические shim-метки. Отдельная ветка — выпущенные id, которых нет в **этой** сборке (пак не
установлен): для них эмитится
`label <id>: unwind_call_stack; vn_unavailable_reason = "missing_content"; jump vn_scene_unavailable`
(`compile.py:534-546`) — игрок получает объяснение вместо `ScriptError`.

**Сегодня защита инертна.** `content/renames.yaml` — все пять секций пусты, `id_registry.json` — все
четыре массива пусты (`assets` схемой разрешён, но в файле его нет), потому что
`stamp_id_registry` пишет туда только главы со `status: "release"`, а единственная глава `ch01_awakening`
— `draft`. Механизм включится сам при первой release-главе; до тех пор `git mv` сцене никто не
поймает.

### 12.2. `save_schema` и миграции

- Счётчик один: `project.yaml: save_schema` (сейчас **2**) → `default vn_save_schema` +
  `define vn_build_save_schema` (`compile.py:171-175`).
- Номер миграции резервируется в `content/migrations/registry.yaml` (`migrations_registry@1`) **в том
  же PR**, что и файл `NNNN_<slug>.py`. Дыра в цепочке и незарезервированный номер — ошибки сборки
  (`test_saves.py`).
- Миграции исполняются **в игре**, в `label after_load` (`020_state.rpy:82-107`): сейв из будущей
  схемы блокируется (`block_rollback` + сообщение + `full_restart`), сейв из прошлой прогоняет
  `vn_state.run_migrations()`. После миграции — Revertable-конвертация и `block_rollback()`: откат за
  точку миграции вернул бы домиграционное состояние.
- **Фикстуру со старой схемой снимать ДО бампа.** После бампа получить сейв на старой схеме уже нечем,
  и корпус станет ложно-зелёным. Порядок — [27-testing.md §9.8](27-testing.md).

### 12.3. `.rpyc` как релизный артефакт (G6)

`.rpyc` генерата подкладывается перед компиляцией следующего релиза — так переносятся
statement-имена. Отсюда два следствия:

- `build/rpyc-cache/<version>/` ключуется **только версией, не флейвором**: собрали public и patron
  одной версии — второй перезаписал носитель имён первого.
- В git лежит ровно одно исключение из `*.rpyc`: `ci/fixtures/rpyc-line/**` (52 файла,
  `.gitignore:9-14`) — линия имён для фикстур сейв-корпуса. Пересоздаёт её `vn save corpus --add`, а не
  человек. Фикстуру и линию коммитить **одним коммитом**: разошлись — корпус красный у всех, а причина
  невидима в диффе.

### 12.4. Совместимость паков

Манифест пака несёт диапазон `api_level` фасада `vn.*`; тулинг сверяет его с `VN_API_LEVEL`
(`compile.py:554`), рантайм — с `API_LEVEL = 1` (`030_flow.rpy:9`). Равенство двух чисел закрыто
тестом `test_engine_compat.py:91`. **Тонкость:** фасад с 2026-08 расширен пятью членами
(`voice_path`, `quality_cap`, `set_quality_cap`, `ui_scale_pref`, `set_ui_scale`) и объектом
`pack_registry`, а `API_LEVEL` остался 1. Добавление члена совместимо назад, поэтому бамп не
требовался; **удаление или смена сигнатуры существующего члена бампа требует.**

## 13. Asset organization

**Зона мастеров — `assets_src/`, в git через LFS.** Актуальная политика — ADR-0012:

```
assets_src/art/{characters,backgrounds,cg,shots}/…    ← основная зона растра
assets_src/png/…                                      ← исторический алиас (pipeline.py:83)
assets_src/audio_stems/{bgm,amb,sfx}/                  ← .ogg
assets_src/voice/<lang>/<chNN>/<line_id>.{wav,flac,ogg,opus}
assets_src/video_src/<group>/<name>.mp4 + <name>.video.yaml
assets_src/{daz,vam,sims4}/**/<name>.render.yaml       ← декларации внешних источников
assets_src/{psd,live2d,spine_export}/                  ← psd читает только psd.py (и только psd/characters/)
```

Зоны `live2d/` и `spine_export/` **не читает ни одна строка тулинга** (`grep -rn 'live2d\|spine_export'
tools/vn/src/` → 0). Путь к ним объявлен только в схеме: `character@1.schema.json:67`,
`^assets_src/(live2d|spine_export)/characters/<key>/`. То есть декларацию написать можно, а собрать
нечем — G12/C20 остаются фазой 3.

Правила:

- **Оба растровых корня сканируются** (`ART_ROOTS = ("art", "png")`). Один и тот же ассет в обоих —
  ошибка «два источника претендуют на один выход»; норма — `art/`.
- **Формат мастера задаётся данными**, не кодом: `project.yaml: render.classes.<c>.formats`
  (bg/cg/shot — png/jpg/jpeg/webp/tif/tiff; spr — png/webp/tif/tiff, потому что альфа обязательна и
  JPEG непригоден). `.psd` в art-зоне — ошибка.
- **Мастер bg/cg/shot меньше `source_min: [3840, 2160]` — ошибка сборки.** «Уменьшить можно потом,
  увеличить — уже никогда» (`project.yaml`). Апскейл запрещён физически: вариант, требующий его,
  пропускается (`render_config.py:198-215`).
- **Альфа — политика класса**: `spr` — `require` (нет альфы = «фон не вырезан», error), `bg`/`cg` —
  `forbid` (альфа будет отброшена, warning), `shot` — по роли слоя: `env` forbid, остальные require.
- **Единый холст**: все слои одной позы обязаны совпадать по размеру с `canvas` из `character.yaml`
  либо с холстом `base`; для шота холст задаёт `env`. Нарушение — «слои одной позы обязаны лежать на
  ОДНОМ холсте».
- **Файл в зоне мастеров, не подобранный ни одной ветвью discovery, — ошибка.** Легальные спутники
  перечислены закрытым списком (`SIDECAR_SUFFIXES`/`SIDECAR_NAMES`, `pipeline.py:87-89`).
- **Бинарь в `assets_src/` обязан быть покрыт Git LFS.** Каждый непокрытый файл — отдельная ошибка
  линта независимо от размера (`lint.py:437`), плюс суммарный порог 50 МБ **только по файлам мимо
  LFS** (`lint.py:445-452`, ADR0004_BINARY_LIMIT_MB). Ответ о покрытии даёт сам git
  (`git check-attr`), а не fnmatch — иначе `.gitattributes` и линтер расходились бы.
- **Одна ошибка discovery останавливает всю сборку ассетов**, включая непричастные ветки: `build_assets`
  собирает ошибки и выходит до первой трансформации. Опечатка в имени папки спрайта роняет и звук, и
  видео.

**Зона выходов `game/assets/` — производная и не в git.** Править её руками бессмысленно тремя разными
способами: файл из манифеста вернётся к сгенерированным байтам, файл вне манифеста не удалится
никогда и поедет в каждый дистрибутив, а `vn build --check` не заметит ни того, ни другого (он сверяет
`src_hash`/`transform`/`profile`, а не байты выхода).

**Версия трансформации.** Правка **данных** (`project.yaml: render.*`, байты sidecar) инвалидирует
ветку кэша сама — они входят в `params_digest`. Правка **кода** трансформации (`assets/imaging.py:104` `encode`,
`assets/video.py:85` `encode_args`, `voice.py:289` `encode_opus`) не меняет ни один вход хеша, поэтому обязана
сопровождаться бампом версии в `TRANSFORMS` (`assets/pipeline.py:54-65`) — иначе кэш вернёт старые байты как
свежие, и это не проверяется ничем.

## 14. Платформенные правила (ADR-0014)

**Единственная точка касания платформы — `game/framework/00_core/035_platform.rpy`.** Игровой код не
знает слова «Steam»: он зовёт фасады ядра (`vn_ach.grant`, `vn.pack_registry.owned`) и
capability-запросы `vn_platform.*` (`is_steam_deck`, `is_big_picture`, `has_touch`,
`controller_first`, `overlay_enabled`, `describe`). Провайдеров подключает этот файл на `init 999` —
после того как реестры загружены и Steam инициализирован движком.

Гард-тест: `test_platform.py:183` пробегает все `game/**/*.rpy` и падает, если `_renpysteam` или
`steamapi` встречаются в любом файле, кроме `035_platform.rpy`.

Прочие правила:

- Интеграция — **штатным стеком движка** (`00steam.rpy` / `00achievement.rpy`), без сторонних
  биндингов.
- Конфиг — данные: `project.yaml: platform.steam.appid` → генерат `platform.gen.rpy`
  (`define config.steam_appid`, `define VN_STEAM_DLC`). `appid: null` = Steam выключен, и это
  **рабочее** состояние, а не поломка.
- Ошибка платформенного API — **fail-open**: гейт владения логический, не DRM (`030_flow.rpy:63-88`).
  Вне Steam `owned()` возвращает True для установленного пака.
- `config.default_fullscreen = True` включается только на controller-first окружениях
  (`options.rpy:15-17`) — на десктопе движковый дефолт не трогаем.

## Частые ошибки

1. **Считать `ARCHITECTURE.md` описанием кода.** Это целевой документ; фактический статус каждой нормы
   — [02-architecture.md §6-7](02-architecture.md).
2. **Верить номеру строки в цитате.** `tools/vn/**` правится чаще всего; ссылки вида `file.py:NNN`
   плывут после каждой вставки блока. Ищите по имени символа, номер — подсказка.
3. **Считать зелёный прогон приёмкой на draft-главе.** `status: draft` выключает часть проверок
   (`lint.py:244,266,305`, `scenes.py:235,261`), и `id_registry` пуст, пока нет release-главы.
4. **Путать `vn content compile --check` и `vn build`.** Первый отвечает только на «свеж ли генерат» и
   на битом YAML даёт `внутренняя ошибка компилятора: KeyError` вместо схемной ошибки. Диагноз —
   всегда `vn build`.
5. **Ждать, что `renames.yaml` починит переименование задним числом.** Он работает только для id,
   которые **уже** попали к игрокам; для сцены, переименованной `git mv` без записи, восстанавливать
   нечего.
6. **Думать, что «зелёный lint ⇒ build не упадёт» — гарантия.** Инвариант объявлен (`lint.py:34`), но
