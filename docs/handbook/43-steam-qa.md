### 1.1 Запуск из Steam-клиента

**Как проверять.** Заполнить `platform.steam.appid`, `vn build`, положить steam_api ([40-steamworks.md](40-steamworks.md) §5.2), собрать дистрибутив, установить его в Steam (или запустить `vn play` при живом клиенте — `steam_appid.txt` из `steam_preinit` это позволяет, §5.4 там же) и посмотреть `log.txt`:

```
Initialized steam.                                   <- движок (00steam.rpy:1062)
[vn] platform: steam deck=False bigpicture=False touch=False   <- наш фасад (035_platform.rpy:89)
```

**Провал:** в логе `Failed to initialize steam: …`; или строка `[vn] platform: standalone` при живом клиенте и положенной библиотеке; или игра вообще не стартует (в этом случае смотреть `traceback.txt`).

**Сегодня: BLOCKED** — `appid: null`, приложения в Steamworks нет. Проверяется только то, что при `appid: null` игра корректно работает как standalone (§1.3).

### 1.2 Первый запуск (чистый профиль)

**Как проверять.** Удалить каталог сохранений целиком (`<savedir>`, см. §0) и запустить. Что обязано быть верно:

- главное меню открывается, `start` ведёт в первую главу через `label start` (`030_flow.rpy:217-223`);
- `persistent.vn_gallery_unlocked`, `persistent.vn_achievements` пустые, галерея показывает закрытые ячейки, а не падает;
- `persistent.vn_quality_cap` и `persistent.vn_ui_scale` — `None`, то есть «авто» (`../../content/variables/settings.vars.yaml`);
- на controller-first окружении первый запуск **сразу в фуллскрине** (`config.default_fullscreen = True` только при `vn_platform.controller_first()`, `../../game/options.rpy:15-17`), на десктопе — оконный.

**Провал:** краш на пустом `persistent`; галерея или экран настроек падают из-за `None`; фуллскрин включился на обычном десктопе (это регрессия `controller_first()`).

Автопилот стартует **не с чистого профиля** (он использует профиль машины, кроме прогонов корпуса с `--savedir`), поэтому «первый запуск» руками отдельно нужен.

### 1.3 Запуск без Steam

Три разных «без Steam», и все три обязаны работать:

| Случай | Как воспроизвести | Ожидание |
|---|---|---|
| Сборка без App ID | текущее состояние репозитория | `define config.steam_appid = None`, `steam_init` не трогает Steam |
| Библиотеки нет рядом с исполняемым | обычная сборка на машине без Install Steam Support | `steam_init` выходит на шаге «нет файла» (`00steam.rpy:1019-1020`), молча |
| Библиотека есть, но Steam выключен принудительно | `RENPY_NO_STEAM=1 <исполняемый>` | тот же standalone (`00steam.rpy:1025-1026`) |

**Как проверять.** Пройти игру от старта до конца контента, открыть галерею, настройки, историю, сохранить и загрузить. В логе — `[vn] platform: standalone` либо вообще ни одной Steam-строки.

**Провал:** любое исключение, ссылающееся на `achievement.steam`, `_renpysteam` или `steamapi`; исчезнувшие карточки глав (при отсутствии провайдера `owned()` обязан быть `True` для установленных паков, `030_flow.rpy:79-86`); ачивки не выдаются локально.

`RENPY_NO_STEAM` — единственный рычаг «выключить Steam при живой библиотеке»: `config.enable_steam` живёт в `python early` движка, и обычный `define` его не переопределит ([40-steamworks.md](40-steamworks.md) §5.1).

### 1.5 Загрузка

**Как проверять.**

```bash
vn save corpus     # каждая фикстура ЗАГРУЖАЕТСЯ в реальной игре, миграции идут в after_load
```

Команда (`../../tools/vn/src/vn/cli.py:1391-1480`) для каждой фикстуры поднимает игру с изолированным `--savedir`, грузит слот `1-1`, доигрывает автопилотом до конца и сверяет фактическую пост-миграционную схему с `project.yaml: save_schema`. Сейчас в `ci/fixtures/saves/` **2 фикстуры**, вторая на старой схеме — то есть миграция реально исполняется.

**Провал:** `✗ <фикстура>: …` в выводе; `schema после загрузки` не равна `save_schema` из `project.yaml`; в логе `migrations incomplete: …` (`../../game/framework/00_core/020_state.rpy:96-107`).

Руками дополнительно: загрузка из главного меню и из игрового меню, загрузка того же слота дважды, откат (`Rollback()`) сразу после загрузки.

### 1.6 Битый, чужой или «будущий» сейв

Три разных сценария:

| Сценарий | Что должно произойти | Где реализовано |
|---|---|---|
| Сейв **новее** текущей сборки (играли на другой машине, там обновились) | `block_rollback()` → сообщение `ui.flow.save_from_newer` → `full_restart()`; вниз не мигрируем | `020_state.rpy:86-95` |
| Сейв **старше** | цепочка миграций, схема поднимается до фактически применённой | `020_state.rpy:96-107` |
| Сейв ссылается на сцену, которой в сборке нет (пак не установлен) | shim-метка → `vn_unavailable_reason = "missing_content"` → экран `vn_content_unavailable` (`../../game/framework/20_ui/screens/unavailable.rpy:11`) | `compile.py:_emit_overrides` (`:510`) |
| Файл слота физически битый (обрезан, не zip) | исключение движка → наш брендированный `screen _exception` с действиями rollback/ignore/quit (`../../game/framework/20_ui/screens/crash_screen.rpy:19-66`) + `crash-*.txt` | `070_crash.rpy` |

**Как проверять.** Первые два — `vn save corpus` (автоматизировано). Третий — собрать `--flavor public` (без пака `nsfw`) и загрузить сейв, сделанный в `patron`-сборке. Четвёртый — руками: скопировать фикстуру, обрезать её `head -c 100`, положить в `<savedir>` и загрузить.

**Провал:** вместо экрана-объяснения игрок получает голый трейсбек Ren'Py; гейт «сейв из будущего» обходится колёсиком мыши (значит `block_rollback` стоит после `say` — это регрессия); `crash-*.txt` не создан и в `log.txt` нет строки `[vn] unhandled exception: …`.

### 1.7 Выход

**Как проверять.** В игре есть два штатных пути `full_restart()`: конец контента (`030_flow.rpy:245-252`) и экран «сцена недоступна» (`:232-243`). Оба проходятся вручную; конец контента дополнительно проходит автопилот в каждом `vn test smoke` (вердикт `OK: vn_end_of_content`).

Ожидание: возврат в главное меню без утечки состояния — `vn_menu`, `vn_scene` и переменные глав сброшены к дефолтам, галерея и ачивки (persistent) **сохранились**.

**Провал:** после рестарта в новой игре видны флаги предыдущего прохождения; рестарт роняет игру; на экране «сцена недоступна» кнопка «В главное меню» не имеет фокуса по умолчанию (`focus_default`, `unavailable.rpy:31`) — на паде это тупик.

**Провал:** любой экран, из которого нельзя выйти падом; кнопка без фокуса по умолчанию в модальном диалоге; список, который нельзя пролистать; нечитаемый кегль; **отсутствие способа откалибровать/переназначить пад** — этого в проекте нет вовсе (движок даёт `GamepadExists()` и `GamepadCalibrate()` — `$RENPY_SDK/renpy/common/00gamepad.rpy:254`, `:271`; наш экран настроек их не использует), поэтому пункт остаётся известным пробелом, а не провалом конкретного прогона.

**Ловушка, о которой надо знать заранее:** варианты `steam_deck` / `medium` / `touch` вставляет **только успешная Steam-инициализация** (`00steam.rpy:1049-1059`). То есть сборка, принесённая на настоящий Deck «мимо Steam» (без App ID и без steam_api), ведёт себя как обычный linux-десктоп: масштаб 1.0, оконный режим, `controller_first()` = `False`. **Сегодня: BLOCKED** для живой части — физического Deck нет. Норма проекта (`../../ci/steam/README.md`): прогон на Deck **обязателен** перед `setlive default`. Способы доставки сборки на устройство — [41-steam-deck.md](41-steam-deck.md).

Джоба `controller-first`: прогон в двух геймпадных профилях (`steam_deck medium touch`, `steam_big_picture`) + шоты `main_menu,preferences,gallery,chapter_select` артефактом | Steam, Deck на железе, ручные пункты; пад-события не эмитируются и здесь. **Внимание:** релизная сборка обоих флейворов в этой джобе сейчас проходит: гейт зрелости контента даёт WARN, пока `release`-глав нет; покраснеет она с первой такой главой ([29 §5.1](29-build-and-release.md#maturity-gate-rule)) |
| CI: `steam-upload.yml` (только ручной запуск) | что `release build` → `release steam` проходят целиком и VDF генерируется | сам аплоад: без секретов `STEAM_USERNAME`/`STEAM_CONFIG_VDF` шаг — no-op, и при `appid: null` workflow падает раньше |

Итог: **автоматика закрывает «игра собирается, запускается, проходится и грузит сейвы». Всё, что делает Steam-сборку Steam-сборкой, закрывается только руками.**

## Чего НЕ делать

- **Не выкладывать в `default`-ветку, не прогнав на живом Steam Deck.** Это норма проекта (`../../ci/steam/README.md`), а не пожелание: smoke под `RENPY_VARIANT` проверяет вёрстку, но не пад, не оверлей и не Steam API.
- **Не считать зелёный CI приёмкой.** CI не запускает Steam, не нажимает кнопки пада и не смотрит на скриншоты. Он гарантирует «собирается и проходится», не более.
- **Не считать `vn release validate` Steam-проверкой** — в его 21 проверке нет ни одной строки про Steam.
- **Не принимать «все PASS» за эталон гейта.** Сегодня штатный вывод для `public` — **20 строк: 18 PASS и два WARN** (`озвучка: 14 черновых дублей (draft)` и `зрелость контента: ни одна глава ещё не доведена до status=release`), exit 0. `ok` становится `False` только на FAIL (`release.py:532-536`), поэтому WARN релиз не валит. `--flavor patron` — 21 строка, один WARN, тоже exit 0. Второй WARN — предупреждение на будущее: гейт зрелости самоактивирующийся и станет строгим с первой главой `status: release` ([29 §5.1](29-build-and-release.md#maturity-gate-rule)).
- **Не проверять первый запуск на своём профиле** — `<savedir>` надо удалить целиком, иначе `persistent` от предыдущих прогонов маскирует ровно те баги, которые ищутся.
- **Не гонять `vn test smoke` вместо ручного прохождения перед релизом.** Автопилот жмёт «дальше» каждые 0.6 с (`030_flow.rpy:_AUTOPILOT_RPY`, таймер в `cli.py:1505`) и не читает текст: опечатки, неверный порядок реплик и рассинхрон озвучки он не увидит.
- **Не забывать `vn build` перед `vn release validate`** — без него pseudo-локаль оценивается как боевой язык и порог покрытия считается неверно.
- **Не оставлять осиротевший `game/generated/qa/autopilot.rpyc`.** Автопилот сам чистит каталог до и после прогона (`cli.py:1530-1534`, `:1560-1566`), но жёстко убитый прогон мог оставить файл — он гейтится `VN_AUTOPILOT`, так что обычный запуск не превратится в самопроигрывание, и всё же перед сборкой каталога быть не должно.
- **Не проверять ачивки, удаляя `persistent` вручную в Steam-сборке** — локальный список опустеет, а Steam свои ачивки помнит; догон (`035_platform.rpy:83-88`) при следующем старте выдаст их снова, и «сброс» будет неполным. Правильный сброс — «Сбросить статистику» в клиенте Steam.
- **Не выкладывать сборку, собранную с `--profile draft`.** Профиль входит в ключ кэша ассетов, но релизный гейт draft от full не отличает (`grep profile tools/vn/src/vn/release.py` → 0). Единственная защита — дисциплина: перед релизом всегда полный `vn assets build`/`vn build` без флага.

## Проверка

Полная последовательность перед выкладкой (по возрастанию стоимости):

```bash
# 1. Холодный слой
vn doctor && vn content lint && python -m pytest tools/vn/tests -q

# 2. Сборка и движковые проверки
vn build
bash "$RENPY_SDK/renpy.sh" . lint
vn test oversample --scale 2
vn content compile --check

# 3. Прогоны (матрица §6)
vn test smoke --picks 0,0 && vn test smoke --picks 0,1 --lang en \
  && vn test smoke --picks 1 && vn test smoke --picks 0,0 --lang pseudo
RENPY_VARIANT="steam_deck medium touch" vn test smoke --picks 0,0
RENPY_VARIANT="steam_big_picture"       vn test smoke --picks 0,0
ls .vncache/smoke/                      # ГЛАЗАМИ

# 4. Сейвы
vn save check && vn save corpus

# 5. Гейт и сборка флейворов
vn release validate --flavor public
vn release build --flavor public --package win --package linux --package mac

# 6. Steam (когда появится App ID)
vn release steam --flavor public --branch beta
steamcmd +login <account> +run_app_build build/steam/app_build_public.vdf +quit

# 7. Руками: §1.1-1.2, §1.7-1.8, §1.11-1.12, §2.1-2.8 на живом Deck и на десктопе
```
