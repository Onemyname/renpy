# 17. DAZ Studio

> **Обновлено ADR-0012:** валидатор деклараций общий для DAZ/VaM/Sims 4 (`assets/sources.py`) и сверяет `id` с `output`, а объявленное `resolution` — с фактическим файлом; заготовка декларации — `vn assets new daz <logical_id> --scene …`; AI-полировка поверх рендера больше не стирает происхождение (провенанс наследуется in-place); выход декларации указывает в `assets_src/art/**`.

> **Статус подсистемы:** PARTIALLY IMPLEMENTED — тулинг вокруг DAZ написан и покрыт тестами (схема `daz_render@1`, валидатор `vn assets daz validate`, провенанс-цепочка, лицензионный гейт, детект установки в `vn pipeline doctor`), **но через него не прошёл ни один рендер**: в репозитории ноль `.duf`, ноль `*.render.yaml`, ноль `*.provenance.json`. Автоматизация самого рендера (DAZ Script, headless, batch) — **NOT IMPLEMENTED**, кода нет вообще. Рендер сегодня — ручной GUI-шаг.
> **Отвечает на вопрос:** «Как из DAZ Studio получить кадр, который доедет до игры, и что вокруг этого кадра обязан сделать конвейер».

DAZ Studio — основной источник визуала проекта: арт-направление зафиксировано ADR-0006 как «DAZ-реализм (стиллы) + AI-анимация Wan 2.2 I2V». Приложение живёт вне репозитория (`D:\DAZ3D\...`), а в репозитории живут три вещи: **декларация** каждого рендера (`assets_src/daz/**/<name>.render.yaml`), **провенанс** его выхода (`<output>.provenance.json`) и **лицензионный учёт** использованных продуктов (`content/licenses.yaml`). Норма — [`../adr/0006-daz-comfyui-video-pipeline.md`](../adr/0006-daz-comfyui-video-pipeline.md); установка окружения — [`../pipeline/phase-0.md`](../pipeline/phase-0.md). В `docs/ARCHITECTURE.md` слова «DAZ» нет ни разу: весь внешний 3D-трек нормирован только ADR-ами.

## Быстрый ответ

```bash
vn pipeline doctor                    # DAZ Studio + библиотека + GPU + ffmpeg + модели
# --- рендер делается руками в GUI ---
# 1) сохранить сцену        -> assets_src/daz/ch01/kiss/scene.duf
# 2) написать декларацию    -> assets_src/daz/ch01/kiss/kiss.render.yaml  (daz_render@1)
# 3) отрендерить в PNG      -> assets_src/png/cg/ch01/kiss.png            (путь = output:)
vn assets daz validate                # схема + наличие сцены + наличие выхода + запись провенанса
vn assets licenses                    # каждый использованный продукт есть в реестре
vn assets build                       # png/cg/** -> game/assets/cg/**.webp + .thumb.webp
vn build                              # + генерат: image cg ch01 kiss
vn release validate --flavor patron   # 19 проверок, из них 3 про DAZ/провенанс/лицензии
```

Сегодня все пять команд выше отработают на пустом множестве: `vn assets daz validate` напечатает «деклараций нет (assets_src/daz/\*\*/\<name\>.render.yaml)» (`../../tools/vn/src/vn/cli.py:674-677`).

**Легенда статусов** в этом файле: `IMPLEMENTED` — код есть и работает; `PARTIAL` — код есть, но покрывает не то, что обещано; `UNEXERCISED` — код есть, но в этом репозитории ни разу не исполнялся на реальных данных; `NOT IMPLEMENTED` — кода нет.

### 2.3 Расхождение: документация проекта отстала от DS6

**Факт:** `../pipeline/phase-0.md:27` и `../../tools/install-daz.ps1:109` требуют «DAZ Studio 4.24+», фактически на машине стоит **ветка 6**. Требование «4.24+» формально выполнено, но вводит в заблуждение: по данным ресёрча **Iray в 4.x скомпилирован до появления Blackwell, и карты 50-й серии там не работают вообще** (модератор форума DAZ: «50x0 cards cannot be supported by Iray in DS 4.x.x.x due to the way the code has been compiled»). То есть на 4.24 + RTX 5080 вы получаете не «медленнее», а **тихий CPU-рендер**. Правильная формулировка нормы — «DAZ Studio 6» и **драйвер NVIDIA ≥ 576.57 (R575), Studio Driver 576.80+**; на машине 610.74 — с запасом.

Что реально изменилось в ветке 6 (по [техническому обзору DS6](https://www.daz3d.com/blog/daz-studio-6-technical-highlights)) и почему это важно нам:

| Изменение в DS6 | Последствие для проекта |
|---|---|
| Iray **2025.0.3** (сборка `387700.2665`), поддержка Blackwell / RTX 50-series | единственная причина, по которой 5080 вообще рендерит |
| OptiX 9.0 | ускорение волос/фибр на Blackwell при линейных сегментах — проверять на своих причёсках |
| DzScript: ECMAScript 5.1 → **ECMAScript 7 / 2016** (классы, `let/const`, стрелки, `Map`/`Set`/`Promise`), плюс подмножество CommonJS `require()` | автоматизация рендера писабельна нормально, а не на ES5 (§9) |

| Удалено: 3Delight, Collada-экспортёр, Dynamic Clothing, Mimic/Mimic Live, Photoshop 3D Bridge, Render Album, Shader Baker, Shader Builder | если в туториале встречается любое из этого — туториал для 4.x |

| Встроенная панель «Victoria AI Chat» | для коммерческого 18+ проекта решите осознанно, хотите ли вы LLM-панель внутри сессии; это вопрос утечки данных, а не удобства |
| Известная проблема — лаги вьюпорта | проверьте на своих сценах до того, как построите на этом график |

**Рекомендация (в хендбуке — не правка кода):** привести `../pipeline/phase-0.md:21-27` и `../../tools/install-daz.ps1:109-110` к «DAZ Studio 6 + драйвер ≥ 576.57». ## 3. Iray под RTX 5080: настройка и приёмка

Проектная норма — `../pipeline/phase-0.md:95-105`. Ниже — она же, развёрнутая, с числами из ресёрча.

### 3.1 Обязательный минимум (делается один раз)

1. **Render Settings → Advanced → Devices:** галка **только** на RTX 5080; **CPU снять**. Смысл контринтуитивен: CPU в списке не «помогает», а **маскирует аварию** — при нехватке VRAM Iray молча уезжает на CPU, и кадр считается в десятки раз дольше. Без CPU-устройства рендер падает явно, и вы чините сцену, а не ждёте.
2. **OptiX Prime acceleration:** включить.
3. **Progressive Rendering:** задать `Max Samples` и `Rendering Converged Ratio` (см. §8), включить `Post Denoiser`.
4. **Бюджет VRAM — 16 ГБ.** Держите сцену заведомо ниже потолка; `Scene Optimizer` (даунскейл текстур 4K→2K для второстепенного) — не опция, а часть библиотеки.

### 3.2 Главный симптом неправильной настройки

**Кадр считается в десятки раз дольше обычного, GPU при этом «молчит».** Причины ровно две: старая ветка DAZ (Iray не знает Blackwell) либо сцена не влезла в VRAM. Диагностика — **строка перечисления устройств в логе Iray в начале каждого рендера**. Смотрите её каждый раз после смены драйвера или заметного роста сцены; в ресёрче это названо самой дорогой ошибкой всего конвейера.

### 3.3 Что реально экономит время (по данным ресёрча)

| Приём | Эффект |
|---|---|
| Уменьшить размер текстур, упростить материалы | до 10× по времени рендера; «textures are infinitely more expensive than models» — даунскейл до 1024 давал большой выигрыш без заметной потери качества |
| Пик VRAM приходится на фазу «Retrieving Geometry» | лечится снижением subdivision, масштабированием текстур, Scene Optimizer / Decimator |
| Рендерить в 2× от целевого разрешения и **уменьшать в постобработке** | убирает шум лучше денойзера и сохраняет микродеталь кожи — денойзер её «замыливает», это самый частый признак дешёвой DAZ-новеллы |
| Останавливаться по `Converged Ratio` (~95%) + потолок `Max Time`, а не по фиксированному `Max Samples` | простые кадры заканчиваются раньше, а не выжигают весь бюджет |
| Убирать геометрию вне кадра, дробить сложные сцены | прямая экономия VRAM |
| LOD по расстоянию: меньше SubD и без HD-морфов для всех, кто не в фокусе | DOF-размытие всё равно это скроет |
| Перезапускать DAZ между сериями рендеров | приложение копит память между последовательными рендерами |
| Отключать SSS/translucency где не видно, гасить лишний спекуляр на волосах, «ghost lights» для интерьеров, Architectural sampler в помещениях | суммарно заметно |

Топ пожирателей VRAM: текстуры высокого разрешения, высокий SubD, HD-морфы, strand-волосы, карты displacement, геошеллы (удваивают меш фигуры), неоптимизированные дубли пропов.

## 4. Библиотека и организация контента

Приложение и библиотека — **на D:**, репозиторий и инструменты — на C: (`../pipeline/phase-0.md:29-38`). Это уже так.

**Правила, которые дороже всего чинить задним числом:**

- **Ставьте через DIM, не через Daz Connect.** DIM кладёт контент обычными файлами и оставляет манифесты — такую библиотеку можно переносить, бэкапить и аудировать. Daz Connect держит контент в непрозрачной БД. Daz Central — **прекращён**, он только предлагает перейти на DIM.
- **Две библиотеки, а не одна:** отдельно контент из магазина DAZ/DIM, отдельно сторонний/ручной. Смешанная библиотека превращает переустановку и аудит лицензий в раскопки.
- **CMS-база — отдельная точка отказа** и по умолчанию лежит **не** в каталоге контента. Бэкапьте её с той же дисциплиной, что и `.duf`-сцены.
- **Smart Content тихо ломается** при рассинхроне метаданных. Лечение: `Content DB Maintenance → Re-Import Metadata`. Выучите до того, как понадобится.
- **Editorial-лицензированные продукты после установки визуально неотличимы** от обычных, а они некоммерческие. Единственная защита — запись в `content/licenses.yaml` **в момент покупки** (§13).
- Путь смены: контент-директория задаётся до первой массовой установки. Переезд позже = перепрописывание путей во всех сценах.

Стратегия бэкапа `D:\DAZ3D\Library` — §15 и [31-storage-and-backup.md](31-storage-and-backup.md).

## 5. Персонаж как исходник идентичности

**Проблема:** в 200 кадрах одной главы Мира обязана быть одним и тем же человеком. Если «персонаж» существует только внутри сцены `.duf`, то каждая новая сцена — новая попытка воспроизвести лицо, и дрейф гарантирован.

**Решение проекта (норма ADR-0006, `../pipeline/phase-0.md:200-206`):** источник идентичности — **Character Preset**, а не сцена. Сцена — это «где и как стоит», пресет — «кто это».

Почему именно Character Preset:

| | Сцена (`.duf` целиком) | Character Preset |
|---|---|---|
| Что несёт | всю обстановку, свет, камеры, всех фигур | одну фигуру: морфы формы, материалы кожи, глаза, волосы |
| Переиспользование | копипаста сцены → расхождения накапливаются | загрузка в любую сцену одним кликом |
| Что ломается при правке | правка света ломает и лицо | правка формы лица распространяется на всё, что грузит пресет |
| Место в декларации | поле `source:` (`^daz/.+\.duf$`) | поле `render.character_presets: [...]` |

Практический контракт:

1. Один пресет на персонажа + при необходимости отдельные пресеты «одежда/волосы» — их имена перечисляются в `render.character_presets` **каждой** декларации, где персонаж в кадре.
2. Имя пресета — стабильное и совпадающее с `id` персонажа из `content/characters/<id>/character.yaml` (`mira`). См. [10-characters.md](10-characters.md).
3. Материалы кожи фиксируются вместе с пресетом. Смена шейдера кожи между главами — это визуальный реткон, и он не отслеживается ничем: `character_presets` — свободный массив строк, валидатор его не проверяет (§10.2).
4. **Всё, что меняется от кадра к кадру** (поза, эмоция, аутфит), задаётся отдельно и попадает в матрицу (§7).

**Статус:** `render.character_presets` — **IMPLEMENTED в схеме, UNEXERCISED**: поле валидируется только как массив строк, никакого реестра пресетов в репозитории нет (ADR-0006 называет его «источником консистентности персонажа», но конвенции именования не задаёт).

## 6. Свет и камеры

Норма проекта отсутствует — это осознанный пробел, который вам предстоит закрыть первым же пилотом. Что фиксирует конвейер: `render.lighting` — **свободная строка** (id HDRI/пресета), `render.camera` — **обязательная непустая строка** (`daz_render@1:24-26`). Значит, весь смысл этих полей держится на вашей дисциплине именования.

Рабочая схема:

| Категория | Камера | Свет | Почему |
|---|---|---|---|
| `spr/**` — спрайты персонажей | **фиксированный ракурс, один на позу** | ровный, нейтральный, без сюжетных теней | спрайт накладывается на разные фоны; смена ракурса между эмоциями = «дёрганый» персонаж |
| `cg/**` — сюжетные CG | кадрирование под сцену | сюжетное: HDRI + трёхточечная доводка | это картина, а не элемент UI |
| `bg/**` — фоны локаций | камера уровня глаз, зафиксированная на локацию | HDRI по времени суток (`day`, `night`, …) | варианты одной локации обязаны совпадать по геометрии кадра |

**Как сохранить фиксированный ракурс — три уровня надёжности:**

1. **Заблокировать камеру** в DAZ (свойство блокировки трансформаций) — защищает от случайного орбитинга мышью.
2. **Сохранить Camera Preset** (или Scene Subset с камерами) — восстанавливается в любую сцену; ресёрч отдельно отмечает это как приём, который спасает после сорванной сцены.
3. **Записать имя пресета в `render.camera`** — тогда даже потерянный пресет виден в провенансе выхода.

Именование: `cam_<назначение>` (`cam_spr_a`, `cam_cg_kiss`, `cam_bg_rooftop`). Строка попадает в `settings` провенанса дословно (`provenance.py:279`) — это ваша единственная связь «кадр → как он снят».

Свет: базовая схема — HDRI (общая экспозиция и заполнение) + трёхточечная доводка (key / fill / rim) для лица. Для интерьеров ресёрч рекомендует эмиссивные «ghost lights» и Architectural sampler вместо внешнего солнца через окно — быстрее сходится.

## 7. Позы и эмоции: матрица из `character.yaml`

Матрица спрайтов **уже объявлена в репозитории** — `content/characters/mira/character.yaml`:

```yaml
canvas: [1200, 2200]
matrix:
  poses: [a]
  outfits: [school, casual]
  emotions: [neutral, smile, angry]
  required:
    - {pose: a, outfits: [school, casual], emotions: [neutral, smile, angry]}
```

Это **контракт для DAZ**: 1 поза × (1 база + 2 аутфита + 3 эмоции) = **6 файлов на позу**. Соответствие имён — жёсткое, потому что имена превращаются в пути и в Ren'Py-атрибуты:

| Что в DAZ | Токен | Файл-сырец | Собранный файл | Ren'Py |
|---|---|---|---|---|
| поза персонажа | `a` | `assets_src/png/characters/mira/a/base.png` | `spr/mira/a/base@2.webp` | `layeredimage mira`, группа `pose` |
| аутфит | `school` | `.../a/outfits/school.png` | `spr/mira/a/outfits/school@2.webp` | атрибут `school` |
| выражение лица | `smile` | `.../a/faces/smile.png` | `spr/mira/a/faces/smile@2.webp` | атрибут `smile` |

Правила, нарушение которых ловится немедленно:

- **Каждый сегмент пути и имя файла обязаны матчить `^[a-z][a-z0-9_]*$`** (`../../tools/vn/src/vn/assets/pipeline.py:48,94-99`). `Smile.png`, `smile-2.png`, `2smile.png` — ошибка сборки, и **весь цикл задач не выполняется**: одно кривое имя не даёт снести `game/assets` каскадом.
- **`base.png` в каталоге позы обязателен** (`pipeline.py:124`), иначе «нет обязательного base.png».
- Токен не может состоять в двух группах матрицы одновременно (проверка дизъюнктности, см. [10-characters.md](10-characters.md)).
- **`canvas: [1200, 2200]` — NOT IMPLEMENTED как контракт**: поле есть в схеме, но его не читает ни одна строка кода (`grep` по `tools/vn/src/vn/` и `game/framework/` — 0 совпадений). Это документация для художника. Виртуальное разрешение игры — 1920×1080 (`game/gui.rpy:9`), спрайты хранятся в 2× (суффикс `@2`), то есть 1200×2200 — это ≈600×1100 виртуальных пикселей.

**Как не потерять соответствие имён между DAZ и репозиторием.** В DAZ нет ничего, что знало бы про `smile`. Единственный мост — имя файла при экспорте. Поэтому: заводите в DAZ пресеты выражений/поз с **теми же токенами** (`face_smile`, `pose_a`, `outfit_school`), а имя выходного файла собирайте из них механически. Пока `.dsa`-автоматизации нет (§9), это дисциплина; когда появится — это тот самый «слой перестановок», который и следует скриптовать.

## 8. Четыре режима работы

Числа семплов — стартовые пресеты из community-гида по Iray (ресёрч), не измерения этого проекта. **Времена рендера в проекте не измерялись**; единственный зафиксированный ориентир — приёмочный рендер 1920×1080 должен уложиться в **5 минут** на референс-машине (`../pipeline/phase-0.md:169-172`).

| Режим | Разрешение | Семплы / сходимость | Денойзер | Когда |
|---|---|---|---|---|
| **Fast preview** (Iray) | 25–50% от целевого | `Max Samples` **500**, `Rendering Quality` 1.0, `Converged Ratio` **85–90%** | вкл. после **80–100** итераций, Firefly Filter вкл., Caustic Sampler выкл. | отбор поз/эмоций, проверка композиции |
| **Standard** | целевое | `Max Samples` **2500**, RQ **1.0–2.0**, `Converged` **95%** | опционально/с задержкой; Firefly вкл., Caustic выкл. | 90% рабочих кадров: CG, фоны |
| **Final render** (портрет/крупный план) | **2× от целевого**, вниз в постобработке | `Max Samples` **4000–8000**, RQ **2.0**, `Converged` **95–98%** | **осторожно или совсем без него на коже**; Caustic Sampler — только для стекла/воды | ключевые CG, лица крупно, обложки |
| **Batch** | как у выбранного режима выше | то же + потолок `Max Time` | как у режима | ночные прогоны серий; **NOT IMPLEMENTED в проекте**, см. §9 |

Для черновых итераций **всей сцены** есть более дешёвый путь, чем Iray: **Filament** — реалтаймовый PBR-рендерер/вьюпорт. Он годится для блокинга камеры, подбора поз и таймингов, **и категорически не годится для отгрузки**: картинка не совпадает с Iray. В схеме `daz_render@1` он допустим (`renderer: iray|filament|viewport`) — используйте это значение честно, чтобы черновик было видно в провенансе.

Связка с профилями сборки ассетов: `vn assets build --profile draft` жмёт WebP до `quality=50` — это про **скорость сборки**, а не про качество рендера, и оно ортогонально режимам выше. Не путайте (см. [16-assets.md](16-assets.md)).

**Те же пресеты под производственными именами** — в [Рендеринг](22-rendering.md) §2: `Fast preview` = `Development`, `Standard` = `Release`, `Final render` = `High Quality`. Это одна и та же таблица с двух точек зрения (режим в DAZ / стадия производства), а не два разных набора настроек.

Скелет ниже собран из этих элементов. **Он не запускался ни в проекте, ни в ресёрче**; способ получения менеджера рендера и синтаксис доступа к значениям enum документацией не подтверждены — сверьте по API reference перед использованием.

```javascript
// render_one.dsa — СКЕЛЕТ, НЕ ПРОВЕРЕН. Верифицированы: scriptArgs, renderImgToId,
// renderImgFilename, imageSize, applyChanges, doRender. Остальное — сверить по API reference.
var out = App.scriptArgs[0];                  // путь выходного PNG, приходит из -scriptArg
var opt = /* DzRenderOptions текущих настроек */;
opt.renderImgToId    = /* RenderImgTarget: DirectToFile */;
opt.renderImgFilename = out;
opt.imageSize        = /* Size(1920, 1080) */;
opt.applyChanges();
/* DzRenderMgr */.doRender( opt );
```

Драйвер снаружи (форма вызова по документации, в проекте не проверялась):

```powershell
$daz = "D:\DAZ3D\Library\Applications\64-bit\DAZ 3D\DAZStudio6\DAZStudio.exe"

    & $daz -headless -noPrompt -instanceName vnrender -scriptArg $out "$PWD\render_one.dsa"
```

- **Справочника API для ветки 6 не существует** — есть только 4.x. Вы пишете по документации 4.x на рантайме Qt6/ES7; дрейф ожидаем.

- Примеры из официальной документации — под **CC Attribution 3.0 Unported**; производные обязаны соблюдать условия.

## 10. Декларация рендера `<name>.render.yaml`

**Схема:** `../../tools/schemas/daz_render@1.schema.json`. `additionalProperties: false` на обоих уровнях — **любой незнакомый ключ = жёсткая ошибка**.
**Куда класть:** `assets_src/daz/**/<name>.render.yaml` (`../conventions/naming.md:20`). Глубина вложенности любая; рекомендуемая — `assets_src/daz/<chNN>/<slug>/`.
**Сколько их в репозитории сейчас:** **ноль**. `assets_src/daz/` содержит только `.gitkeep` (0 байт). Шаблона и скаффолда нет: команды `vn assets daz new` не существует, YAML пишется руками по схеме. Единственный конкретный пример в кодовой базе — фикстура теста `../../tools/vn/tests/test_provenance.py:124-135`.

### 10.1 Полная таблица полей

| Ключ | Обяз. | Тип / ограничение | Строка схемы |
|---|---|---|---|
| `schema` | ✅ | const `daz_render@1` | `:7` |
| `id` | ✅ | `^(bg\|cg\|spr\|mov)/[a-z0-9_/]+$` — логический id результата | `:8` |
| `source` | ✅ | `^daz/.+\.duf$` — сцена относительно `assets_src/` | `:9` |
| `output` | ✅ | `^(png\|video_src)/.+` — ожидаемый рендер относительно `assets_src/` | `:10` |
| `render` | ✅ | объект (ниже) | `:17` |
| `version` | ❌ | integer ≥ 1 — бампается при пере-рендере с новыми настройками | `:11` |
| `license` | ❌ | массив строк `^[a-z][a-z0-9_]*$` — id из `content/licenses.yaml` | `:12-16` |
| `render.resolution` | ✅ | массив ровно из 2 int ≥ 16 | `:20-23` |
| `render.renderer` | ✅ | enum `iray` \| `filament` \| `viewport` | `:24` |
| `render.camera` | ✅ | строка, minLength 1 | `:25` |
| `render.lighting` | ❌ | свободная строка (HDRI/пресет) | `:26` |
| `render.character_presets` | ❌ | массив строк — пресеты формы/материалов | `:27-30` |
| `render.quality` | ❌ | свободный объект: `max_samples`, `denoiser`, … | `:31` |

Реальный пример (фикстура `test_provenance.py:124-135`), расширенный полями, которые стоит заполнять всегда:

```yaml
schema: daz_render@1
id: cg/ch01/kiss
source: daz/ch01/kiss/scene.duf
output: png/cg/ch01/kiss_render.png
version: 1
license: [g9_starter_essentials]
render:
  resolution: [3840, 2160]        # 2× от целевого 1920×1080 — downscale в постобработке
  renderer: iray
  camera: cam_cg_kiss
  lighting: hdri_bedroom_night
  character_presets: [mira]
  quality: {max_samples: 4000, converged_ratio: 0.96, denoiser: false}
```

### 10.2 Что делает `vn assets daz validate` — по шагам

`../../tools/vn/src/vn/cli.py:657-679` → `../../tools/vn/src/vn/assets/daz.py:31-77`. Флаги: `--scope <подпуть>`, `--no-provenance`.

1. Рекурсивный обход `assets_src/daz/**/*.render.yaml` (`daz.py:42`). Каталога нет → пустой отчёт молча (`daz.py:39-40`).
2. Валидация JSON-схемой через `SchemaRegistry` (`daz.py:47-50`). **При ошибке схемы декларация пропускается целиком** (`continue`) — остальные проверки по ней не идут.
3. Существование сцены: `assets_src/<source>` **или** `assets_src/<source>.manifest.json` (`daz.py:53-58`). Текст ошибки: «сцены … нет ни локально, ни в манифестах (vn assets push после сохранения .duf)».
4. Дубли `output` между декларациями (`daz.py:60-64`).
5. Наличие выхода: если `assets_src/<output>` нет — **только WARNING** «выход … ещё не отрендерен», и обработка этой декларации на этом кончается (`daz.py:66-68`).
6. Если выход есть и не задан `--no-provenance` — пишется/обновляется `<output>.provenance.json` (`daz.py:70-76` → `provenance.record_daz`).

Выход: exit 1 при любых ошибках, иначе зелёная строка «daz validate: OK (N деклараций, M предупреждений)».

`--no-provenance` — режим «только проверить»: сайдкары не создаются и не обновляются. Ровно так валидатор вызывается из релизного гейта (`../../tools/vn/src/vn/release.py:347-356`, `write_provenance=False`) — гейт не должен ничего писать в рабочее дерево.

### 10.3 Чего валидатор **не** делает

- **Не открывает и не парсит `.duf`** — это чистая проверка существования файла.
- **Не сверяет `render.resolution` с реальными размерами PNG.**
- **Не проверяет, что `id` согласован с `output`**: `id: cg/ch01/kiss` при `output: png/cg/ch99/other.png` проходит.
- **Не проверяет `character_presets`, `camera`, `lighting`** ни против чего — это свободные строки.
- **Не требует `license`** — отсутствие даёт WARN только в `vn assets licenses` (`../../tools/vn/src/vn/assets/licenses.py:104-108`).
- **Ничего не рендерит.**
- Мелочь, которая путает: если сцены нет, а выход есть, вы получите **две** ошибки на одну декларацию — от шага 3 и от `record_daz`, который тоже упрётся в отсутствующий источник (`provenance.py:274-277`).

### 10.4 Провенанс: что пишется

`record_daz` (`provenance.py:294-296` → `_record_render:266-291`) кладёт **в начало цепочки** шаг:

```json
{"kind": "daz_render",
 "source": {"path": "daz/ch01/kiss/scene.duf", "hash": {...}},
 "declaration": "daz/ch01/kiss/kiss.render.yaml",
 "settings": { … дословный снимок блока render: … }}
```

Хвост цепочки (шаги `comfyui` / `manual`) сохраняется; предыдущий шаг-происхождение любого движка (`*_render`) **заменяется** — у артефакта один источник. Хэши — blake3. Сайдкары ведутся **только внутри `assets_src/`** (`provenance.py:50-59`, норма G2). Подробности AI-шага — [20-image-generation.md](20-image-generation.md).

### 10.5 Дыры гейта, о которых надо знать

| Дыра | Последствие |
|---|---|
| Неотрендеренный выход — **WARN, не FAIL** (`daz.py:66-68`) | декларация без картинки не блокирует релиз |
| **PNG без сайдкара провенанса проходит все проверки**: `provenance.verify()` обходит только существующие `*.provenance.json` | «запиши провенанс при генерации» — дисциплина из `../onboarding/artist.md`, ничем не форсированная |
| Декларация без `license` — WARN | покрытие реестра лицензий фактически не обязательно |
| Провенанс **не протекает** в манифест сборки и в `mov_meta@1` | связь «отгруженный ассет → цепочка» восстанавливается вручную сопоставлением blake3 `src_hash` |

## 11. Именование и версионирование рендеров

| Сущность | Паттерн | Пример |
|---|---|---|
| Декларация | `assets_src/daz/**/<name>.render.yaml` | `assets_src/daz/ch01/kiss/kiss.render.yaml` |
| Сцена | `assets_src/daz/**/<name>.duf` | `assets_src/daz/ch01/kiss/scene.duf` |
| Логический `id` | `^(bg\|cg\|spr\|mov)/[a-z0-9_/]+$` | `cg/ch01/kiss` |
| Выход-стилл | `png/cg/<chNN>/<slug>.png` | `png/cg/ch01/kiss_render.png` |
| Выход-видеосырец | `video_src/<group>/<name>.<ext>` — **группа обязательна** | `video_src/ch01/kiss_loop.mp4` |
| NSFW | подпапка `nsfw/` **внутри категории** | `png/cg/nsfw/ch01/scene01.png` |

Правила:

- **Привязка к главе — через сегмент пути `chNN`**, не через отдельное поле: в схеме `daz_render@1` полей главы/сцены нет. Практически это единственный способ ответить «какие рендеры относятся к ch01» и работать `--scope ch01`.
- **Слуг — только в имени файла и папки.** В `id` слуг не входит: слуг можно менять, id — никогда (G7, `../conventions/naming.md:27`).
- **Пере-рендер с новыми настройками = бамп `version`**, а не новое имя. Имя выхода стабильно, чтобы не плодить осиротевшие ассеты.
- **Смена `id` = новый id + запись в `content/renames.yaml`** — id неизменяемы навсегда.
- **NSFW-подпапка — публичный контракт, а не пожелание:** public-флейворы вырезают `game/assets/*/nsfw/**` на этапе distribute (`release.py:191-202`). Ошиблись папкой — 18+ уехал в публичный билд. Гейт проверяет соответствие каталогов, но не содержимое; ревью контента — на людях. См. [29-build-and-release.md](29-build-and-release.md).

## 12. Экспорт из DAZ: что именно сохранять

| Категория | Формат | Куда | Требования |
|---|---|---|---|
| CG-стилл | **PNG** | `assets_src/png/cg/<...>/<name>.png` | вложенность любая, каждый сегмент — slug |
| Фон локации | PNG | `assets_src/png/backgrounds/<loc>/<variant>.png` | варианты одной локации совпадают по кадру |
| Слой спрайта | PNG **с альфой** | `assets_src/png/characters/<key>/<pose>/{base,outfits/*,faces/*,overlays/*}.png` | `base.png` обязателен |
| Кадр-затравка для Wan I2V | PNG | обычно `assets_src/png/cg/**`, дальше вручную в ComfyUI | — |
| Готовый клип | mp4/mov/mkv/webm/m4v/avi | `assets_src/video_src/<group>/<name>.<ext>` | без группы — ошибка сборки |

Что делает конвейер дальше (`../../tools/vn/src/vn/assets/pipeline.py:82-91,148-157`): открывает PNG через Pillow, **принудительно приводит к RGBA**, кодирует WebP (`quality=90` для cg/bg, `95` для спрайтов; `draft` — 50), и для каждого CG дополнительно делает `*.thumb.webp` (`quality=80`, 512 px по длинной стороне, LANCZOS) — им пользуется галерея, см. [15-gallery.md](15-gallery.md).

**Три ловушки экспорта:**

1. **Альфа не появится из ничего.** `convert("RGBA")` у непрозрачного PNG даёт полностью непрозрачный альфа-канал. Спрайт, отрендеренный на фоне, соберётся **без единой ошибки** и покажется в игре прямоугольником поверх фона. Приёмка слоя спрайта — «в PNG есть реальный альфа-канал», а не «сборка зелёная». (Какой именно переключатель Iray даёт прозрачный фон, в ресёрче проекта не верифицирован — проверяйте в своей сборке DS6.)
2. **Схема декларации допускает имена, которые сборка отвергнет.** `output` валидируется как `^(png|video_src)/.+` — то есть `png/cg/ch01/Kiss-01.png` пройдёт `vn assets daz validate` и упадёт в `vn assets build` («слаг» по `pipeline.py:48`). Проверять надо обеими командами.
3. **Разрешение декларации ≠ разрешение файла.** Если вы рендерите в 2× и уменьшаете в постобработке, `render.resolution` должен описывать **рендер** (то, что делал Iray) — это его смысл в провенансе; итоговый размер файла не сверяется ни с чем.

**Про `canvas: [1200, 2200]` из `character.yaml`:** это ориентир художнику, а не контракт (§7). Реальный размер спрайта задаётся тем, что вы экспортировали.

Дисциплина проекта (`content/licenses.yaml:5-11`): **покупка ассета → запись в реестр → только потом первый рендер с ним.** Ретрофит стоит дорого — придётся пробивать SKU каждого продукта по сотням деклараций.

### 13.1 Механика в репозитории — IMPLEMENTED


| Условие | Код |
|---|---|
| `license:` ссылается на несуществующий id реестра | `licenses.py:90-92` |
| Запись помечена `game_use: false` | `licenses.py:94-98` |
| Запись помечена `nsfw_allowed: false`, а `output` идёт в `nsfw/`-зону | `licenses.py:99-103` |
| Декларация вообще без `license:` | **только WARN** — `licenses.py:104-108` |

`purchased_at` пишите **в кавычках** — иначе YAML отдаёт date-объект вместо строки (замечание прямо в файле, `content/licenses.yaml:29`).

### 13.2 Официальные документы — читать перед коммерческой дистрибуцией

- EULA: **https://www.daz3d.com/eula**
- Типы лицензий (Standard / Editorial / Interactive / 3D Printing): **https://www.daz3d.com/daz-licenses**
- Interactive License: **https://www.daz3d.com/interactive-license-info**

**Здесь не даётся юридических выводов.** Что фиксирует ресёрч как факты о тексте: EULA не имеет ни номера версии, ни даты вступления в силу (только «© 2026 Daz Productions Inc.»); раздел 1.0 разрешает включать производные 2D-изображения в свои работы и распространять их, и запрещает распространять продукты, из которых сам Content может быть отдельно извлечён/декомпилирован; страница Interactive License отдельно упоминает случай «стека рендеров, например спрайта», для которого достаточно стандартного соглашения. Комментарий в `content/licenses.yaml:13-16` отражает ровно эту логику.

**Отдельный пункт, который влияет на архитектуру нашего конвейера:** раздел 1.0 EULA содержит запрет на использование Content «in connection with» AI-движками/системами «with capabilities or instructions to auto-generate materials» с перечислением конкретных продуктов. Наш конвейер по ADR-0006 — это ровно DAZ-рендер → ComfyUI (img2img / I2V). **Проверьте актуальную формулировку EULA по официальной ссылке перед коммерческой дистрибуцией и, если ветка DAZ→ComfyUI становится несущей, получите письменное разъяснение от DAZ или консультацию юриста.** Ни хендбук, ни ADR-0006, ни ADR-0008 юридической оценки не дают.

Прочее, что стоит помнить: **Editorial**-продукты некоммерческие и после установки неотличимы от обычных; **Interactive License** покупается по продукту и нужна, только если в игру уезжает 3D-ассет, а не пиксели; контент **Premier** лицензионно привязан к активной подписке. Модельные лицензии AI-стека (Wan, bigASP, Civitai-LoRA) — отдельная тема ADR-0008, он **не принят**; см. [33-security-and-legal.md](33-security-and-legal.md).

## 14. Типичные ошибки

| Симптом | Причина | Лечение |
|---|---|---|
| Кадр считается в десятки раз дольше, GPU «молчит» | тихий CPU-fallback: старая ветка DAZ (4.x не умеет Blackwell) либо сцена не влезла в VRAM | ветка 6 + драйвер ≥ 576.57; снять CPU в Devices, чтобы падало явно; Scene Optimizer; проверять строку устройств в логе Iray |
| Iray «found no usable devices» на RTX 50xx | DAZ Studio 4.x — Iray собран до Blackwell | только переход на ветку 6, обходного пути нет |
| Рендер стартует, но упирается в VRAM на фазе «Retrieving Geometry» | текстуры/SubD/HD-морфы/strand-волосы/геошеллы | даунскейл текстур (до 1024 для второстепенного), меньше SubD, Decimator, убрать геометрию вне кадра |
| Сторонний плагин/скрипт не работает после перехода на 6 | Qt6: плагины требуют пересборки авторами | ждать обновления от вендора; для очередей рендера предпочитать standalone-инструменты плагинам |
| Пункты меню и Favorites исчезли после перехода на 6 | они не мигрируют с 4.x | завести заново; не планировать перенос рабочего места |
| Спрайт в игре — прямоугольник с фоном | PNG без альфы; Pillow сделал непрозрачную RGBA | пере-экспорт с прозрачным фоном; приёмка — наличие альфа-канала, а не «зелёная сборка» |
| `vn assets daz validate` зелёный, `vn assets build` красный: «слаг» | `output` прошёл слабый паттерн схемы, но нарушает `^[a-z][a-z0-9_]*$` | переименовать выход в нижний регистр без дефисов; всегда прогонять обе команды |
| «сцены …duf нет ни локально, ни в манифестах» | `.duf` не лежит рядом и не запушен | положить локально или `vn assets lock` + `vn assets push`; **но хранилища на этой машине нет** — см. §15 |
| Персонаж «плывёт» между главами | лицо/материалы живут в сцене, а не в Character Preset; либо сменили шейдер кожи | вынести идентичность в пресет, перечислять его в `render.character_presets`; смена шейдера кожи ничем не отслеживается |
| Эмоция/аутфит не появились в игре | имя файла не совпало с токеном `matrix` в `character.yaml` | привести имя к токену; помните: одна кривая ошибка discovery отменяет **весь** цикл задач сборки |
| Кадр N и N+1 расходятся по одежде/волосам без причины | dForce-симуляция не детерминирована между прогонами | симулировать один раз, сохранить состояние и заморозить |
| Пятна/z-fighting на коже под скользящим углом | offset геошелла не подогнан под фигуру/аутфит | подгонять offset per-figure per-outfit; помнить, что шелл удваивает меш в VRAM |
| Кожа выглядит «пластиковой», деталь пропала | агрессивный денойзер на финальном кадре | рендерить в 2× и уменьшать в постобработке; на портретах денойзер осторожно или совсем без него |
| Smart Content не находит только что установленное | рассинхрон метаданных CMS | `Content DB Maintenance → Re-Import Metadata` |
| `vn content lint` краснеет «assets_src: бинарей на N МБ > порога ADR-0004» | `.duf` и PNG-рендеры считаются бинарями | §15 |
| `vn pipeline doctor` зелёный, но рендерить нечем | DAZ/GPU/ComfyUI дают **WARN**, не FAIL | не использовать как гейт; читать строки, а не exit code |

## 15. Хранение и бэкап DAZ-контента

Три разных набора данных, три разных режима:

| Что | Где | Режим | Риск потери |
|---|---|---|---|
| Приложение + библиотека магазина | `D:\DAZ3D\Library\...` | восстанавливается переустановкой через DIM по аккаунту | низкий (но долгий — десятки ГБ) |
| **CMS-база** (метаданные Smart Content) | **не** в каталоге контента | бэкап руками | **высокий** — переиндексация вручную дорога |
| **Ваши сцены `.duf`, пресеты, камеры** | `assets_src/daz/**` | git + хранилище сырцов | **невосстановимо** |

**Главная нерешённая проблема прямо сейчас.** ADR-0006 требует, чтобы `.duf` жили в хранилище (`vn assets push`), а в git попадали только `*.manifest.json`. Но:

- `.vnstorage.yaml` объявляет `default: {type: file, path: "~/vn-assets-store"}`, и **этого каталога на машине не существует** — `vn assets status` печатает «манифестов нет — сырцы ещё не пушились». Бэкенд `type: s3` честно кидает `StorageError` — **NOT IMPLEMENTED** (`tools/vn/src/vn/assets/storage.py:129-133`).
- Значит, единственный доступный путь сегодня — держать `.duf` локально в `assets_src/daz/**`.
- А `vn content lint` считает **все** нетекстовые файлы под `assets_src/` (расширения вне `{.json,.yaml,.yml,.md,.txt,.gitkeep}`): **warn на 30 МБ, error на 50 МБ** (`../../tools/vn/src/vn/content/lint.py:47,371-399`, норма ADR-0004). `.duf` и PNG-рендеры считаются полностью.
- `assets_src/` **не в `.gitignore`** — случайный `git add` закоммитит бинарь в append-only историю.

Порядок действий, пока хранилище не поднято: рендеры-исходники PNG **не держать** в `assets_src/` дольше, чем нужно для `vn assets build` (собранные WebP живут в `game/assets/`, которого нет в git); `.duf` бэкапить внешним средством и **следить за строкой лимита в `vn content lint`**. Развёртывание хранилища — задача с приоритетом; подробности и рецепты — [31-storage-and-backup.md](31-storage-and-backup.md) и [16-assets.md](16-assets.md).

## 17. Чего НЕ делать

- **Не рендерить на ветке DAZ Studio 4.x с RTX 5080.** Это не «медленнее» — Iray там не видит карту, и вы получаете CPU-рендер. Норму «4.24+» в `../pipeline/phase-0.md:27` читайте как устаревшую (§2.3).
- **Не оставлять CPU в списке устройств Iray.** Он превращает явную аварию в тихую десятикратную потерю времени.
- **Не считать `vn pipeline doctor` гейтом рендер-способности** — DAZ, GPU, ComfyUI и модели дают WARN; команда вернёт 0 на машине, где рендерить нечем.
- **Не считать зелёный `vn assets daz validate` подтверждением того, что рендер правильный.** Он не открывает `.duf`, не сверяет разрешение, не сверяет `id` с `output` и не смотрит на картинку.
- **Не переименовывать PNG из ComfyUI до `vn assets provenance record`** — параметры генерации извлекаются из метаданных файла, и потерять их можно ровно один раз (`../onboarding/artist.md`).
- **Не класть 18+ куда-либо, кроме подпапки `nsfw/` своей категории.** Гейт флейворов работает по каталогам; ошибка = 18+ в публичной сборке.
- **Не рендерить с продуктом, которого нет в `content/licenses.yaml`.** Восстановить учёт задним числом по сотням деклараций дороже, чем завести запись при покупке.
- **Не полагаться на `canvas` в `character.yaml`** — поле не читает ни одна строка кода.
- **Не строить внешность персонажа на Premier-эксклюзивном контенте**, если не готовы держать подписку бессрочно: лицензия на такой контент действует, пока активна подписка.
- **Не копить `.duf` и 4K-PNG в `assets_src/`** — порог ADR-0004 (warn 30 МБ / error 50 МБ) покраснит линт и CI, а `assets_src/` не в `.gitignore` (§15).
- **Не искать пути DIM в `AppSettings.ini`** — их там нет; `Software64Path`/`CurInstallPath` живут в `UserAccounts\*.ini` (§2.1).
- **Не переносить чужие туториалы 4.x буквально**: 3Delight, Collada, Dynamic Clothing, Mimic, Photoshop 3D Bridge, Render Album, Shader Baker/Builder в ветке 6 удалены.
- **Не пере-симулировать dForce между соседними кадрами** — результат не бит-в-бит воспроизводим, и одежда «дышит» на монтаже.
