# VN — коммерческая визуальная новелла на Ren'Py

Фундамент проекта описан в **[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)** — это нормативный документ
(решения G1–G24 и C1–C24 в разделе 0 — контракт: код и процессы, противоречащие им, не проходят ревью).

## Быстрый старт

```bash
git clone <repo> vn && cd vn
pip install -e tools/vn          # временно; однокомандный инсталлер по ролям — фаза 1
vn doctor                        # самодиагностика окружения
vn build                         # схемы → компиляция контента → генерат
```

Запуск игры: `vn play` (требует Ren'Py SDK — путь в переменной `RENPY_SDK`; `vn doctor` подскажет).

## Что вы никогда не делаете руками

- не правите `game/generated/`, `game/assets/`, `game/tl/` — это производные зоны, их перезапишет сборка;
- не пишете label вне контракта `<full_id>__*` в сценах;
- не переиспользуете и не переименовываете id (сцен, глав, персонажей, переменных) — только `content/renames.yaml`;
- не пушите сырцы без лока (`vn assets push` без лока откажет).

## Карта репозитория

| Зона | Что это |
|---|---|
| `content/` | Источник истины: декларации (YAML) + авторские `scene.rpy` |
| `packs/` | DLC-контент: один пак = одно дерево, зеркалящее `content/` |
| `game/framework/` | Рукописный код надстройки (ядро, системы, UI, debug) |
| `game/generated/` | Генерат Content Compiler — **не в git** |
| `game/assets/` | Собранные ассеты — **не в git**, `vn bootstrap` |
| `assets_src/` | Сырцы: в git только `*.manifest.json`, бинари в S3 |
| `loc/` | Обмен с переводчиками: PO + шардированный ledger |
| `tools/vn/` | Единственный CLI проекта |
| `tools/schemas/` | Реестр JSON Schema — единственный источник версий схем |
| `docs/` | Архитектура, ADR, конвенции, runbooks, онбординг |

Статус: **фаза 0** (фундамент репозитория) — см. раздел 8 ARCHITECTURE.md.
